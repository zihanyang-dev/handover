# A2A 协议

> 想于 2026-08,**没有查规范原文**。A2A 从发布到捐给 Linux 基金会一直在动(agent card 的路径、
> 版本都改过),下面关于它的每一句都要重查之后才能用。**没有决定,没有建。**

## 要回答的问题

以后会接 A2A 吗?

## 结论:不做成内部模型,以后可能做成一扇门

### 它能接在哪儿:三个位置,只有两个说得通

```
① 我们 ↔ agent          接不上。我们驱动的是别人电脑上的 CLI,各自的 SDK。
                        哪天 Codex 自己开了 A2A server,那是多一个 adapter,不是我们换协议
② 别人 → 我们            说得通。你的 CI / 编排器把一件活交给你笔记本上的 agent
③ 我们 → 远端 A2A agent  说得通,而且不违反 07 ⑥ ——
                        07 禁的是「agent 挑别人的笔记本」,远端服务不是谁的笔记本
```

### 形状已经对上了,所以现在不用为它设计

我们在 `04` 自己长出来的东西,和 A2A 的任务模型几乎一一对应:

```
我们                             A2A 那边大致对应的
tasks.goal                       task 的输入
working / wait / sleep / done    working / input-required / … / completed
takeBack                         cancel
outputs 表                       artifact
transcript                       message 流
```

`wait`(它问你,只有你能让它继续)对上 `input-required` 不是巧合 —— **两边都在建模「你走开之后还
在跑的活」**,同一个问题会长出同一个形状。

所以真要开那扇门,是在现有模型外面糊一层翻译,**不是改我们的模型**。反过来做才是错的:把一个还在
动的外部规范当成内部词汇,就是把别人的形状写死进来。

### 一个看起来冲突、其实不冲突的地方

A2A 有 webhook 推送(长任务完成时回调),而我们整个机器层的地基是「**机器永远不被推送,它只会自己
来问**」。

不打架:那条规矩是关于**机器**的(它在 NAT 后面、会休眠、没有地址)。我们的**服务端**是一个正常的
HTTP 服务,收发 webhook 没有问题。

### 真正缺的不是协议,是身份

和 [外面的东西想让 agent 干活](outside-things-that-want-an-agent.md) 卡在同一个地方:今天进得来
的只有浏览器会话和机器凭据。要开这扇门,先得回答「谁在敲门,他能碰哪个 Space」。

那是一片独立的活;做完之后,**A2A 只是众多可以挂上去的形状之一**。

### 什么时候值得做

等到有一个真实的、外部的东西想给我们派活的时候。在那之前它是一个没有消费者的抽象层 —— 和 `07`
里拒绝掉的那个版本闸是同一类错误(`code-style.md` §7:新依赖必须当前就有消费者)。

顺序上它排在「它做完了会来找你」后面,理由同上一篇。
