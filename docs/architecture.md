# Handover 架构

只写**不随功能变化**的部分:拓扑、模块种类与依赖方向、权威归属、结果三态、不建什么。

具体有哪些 owner、身份怎么构成、事务怎么写、协议长什么样 —— 见对应旅程的 `design.md`。
用户能做什么、系统承诺什么 —— 见对应旅程的 `prd.md`。

## 1. 拓扑

```
浏览器 ──成员会话──► Server ──┐
                        ▲      │ 记录目标
                        │ 拉取 │ 数据库裁决
                        │      ▼
                    常驻进程 ──► agent 进程
```

- **Web 是唯一的人类界面。** 机器上的命令只做接入、保持在线、以及让 agent 提交它被授权提交的东西。
- **Server 不向常驻进程推送。** 常驻进程主动拉取,并在数据库里 claim。
- **Server 可以向浏览器推送。** 推送的内容是临时的,**不是真相**。
- Server 不启动 agent 进程。常驻进程不决定权限、不决定持久真相、不决定 claim 归属。

依赖只有一个方向:**边界依赖 owner,owner 不依赖任何边界。**

## 2. 三种模块

| 种类        | 拥有                                   | 例                                |
| ----------- | -------------------------------------- | --------------------------------- |
| **owner**   | 一类事实的词汇、纯规则、恢复错误       | 一个事实域                        |
| **adapter** | 一个具体外部进程或服务的对接           | 一个 agent 运行时                 |
| **边界**    | 组合、翻译、适配 —— **不拥有产品策略** | 持久化 · 入站传输 · 常驻 · 命令行 |

owner 模块**不导入**任何边界模块。这个方向由设计和完整 diff 的人工评审保证,不扫描业务目录来推断。

**新增一个 owner** 必须同时满足:有独立身份与生命周期 · 保护相邻 owner 表达不了的权限或并发边界 · 当前就有消费者。

**派生而非存储**:任何能从已有事实查出来的东西不建表、不建 owner。

## 3. 权威

- 所有 winner 由数据库决定,不由进程内锁决定。
- 事务前的预检查只改善错误体验,**不授予最终权限**。可并发变化的事实必须在锁读之后、写转移之前重新校验。
- 权威时间全部来自数据库。除非是纯计算,`now` 不穿过命令层。
- 幂等、唯一 winner、唯一性约束由唯一索引强制。**迟到的写者必须在 SQL 里失败。**
- 网络调用不在数据库事务里。先持久化提交事实,再在事务外调用并记录结果。

事务顺序(不适用时不强凑):

```
begin → 锁读权威事实 → 拒绝终态或重放 → 重新校验权限
      → 写唯一的状态转移 → 记录有后果的提交 → commit
```

跨 owner 的事务写在一个文件里,**文件头写明锁序**,所有调用方遵守同一顺序。

## 4. 结果三态

```
succeeded   确定成功
failed      确定失败,重试安全
unknown     不知道,重试可能重复外部后果
```

- 任何外部调用**拿不到确定信号就是 `unknown`**。协议终态、进程退出、对方空闲,都不单独证明成功。
- **`unknown` 永不被猜成前两者,永不自动重放。**
- 重试由人显式发起,且**一次重试授权只能被一个后继执行消费**。
- 未提交的模型输出不是真相。它可以被显示,但不落库。

## 5. agent 的边界

- 具体 adapter 拥有进程生命周期、原生协议、临时目录清理。**不为对称暴露共同的生命周期接口。**
- adapter 声明自己支持哪些能力。请求一个它不支持的能力**响亮失败**,不接受了再忽略。
- agent 只获得当前这件事所需的有界上下文,也只能改变当前这件事的事实。
- agent 不持有人的凭据,**没有绕过它所在的常驻进程直连 Server 的路径**。

## 6. 明确不建

Event Sourcing · workflow 引擎 · provider/model registry · 通用 session owner
参与者 owner · 通知 owner · 调度 owner · 跨 owner 的 helper 模块
把某个 agent 协议当成核心 wire · 把版本库当成事实的身份
