# 机器与 agent

一条完整的纵向:**Space 是空的 → 接一台机器 → 它出现在里面,带着它有的 agent**。

还不跑任何东西。这一片的终点是**能接上、能看到、能拔掉**。

**本文件不定布局。** 只写用户能做什么、被告知什么、失败时怎么办。

---

## 旅程

### ① 空 Space 说自己缺什么

进到一个还没有机器的 Space,看到的不是空白,是一句话和一条命令:

> 这里还不能跑任何东西。Agent 跑在**你的**机器上,不在我们这。

**为什么是你的机器,要在他跑命令之前说。** 他即将在自己的电脑上执行一串东西,得先知道那串东西是干嘛的。

### ② 接一台机器

```
handover connect
```

命令打印一个短码和一个网址:

```
在任意一台能开浏览器的设备上打开   https://…/connect
输入这个码                        WDJB-MJHT

或者直接打开                      https://…/connect/WDJB-MJHT
```

**"任意一台设备"是这句话的重点。** 跑命令的机器可能是一台没有浏览器的服务器,而批准这件事和它在哪台机器上无关。

两行都给,因为两种情况都真实存在:**能从终端复制的时候点第二行,拿手机对着服务器屏幕的时候念第一行的八个字符。** 但第一行是主路径 —— 只给长网址的话,输错一个字符得到的是找不到页面,而不是「这个码不对」。

码里**没有数字也没有元音**,所以不会有 `0` 和 `O` 的问题,也不会随机拼出一个词。

### ③ 批准

浏览器上看到的是**这台机器自称是什么**,你只回答一个问题:

> `mina-mbp` 想接进来。这是你刚才敲命令的那台吗? [ **是我的** ]

**不问「进哪个 Space」。** 那是一台笔记本,笔记本属于它的主人 —— 而你在几个 Space 里是另一回事。
问一遍等于让你决定一件**从「你已经在哪儿」自动跟着走**的事。

批准之后,终端那边自己就好了,不用回去粘任何东西。

**没批准之前它什么都不是。** 不占名字、不出现在列表里、不能读任何东西。

### ④ 看到它

Space 里出现这台机器:名字、是谁的、在线、以及**它上面有哪些 agent**。

```
mina-mbp                在线                    [ 断开 ]
  Claude Code   2.1.4
  Codex         0.9.0

build-server-1  Kai 的  在线
  Claude Code   2.1.4
```

**别人的机器上没有「断开」。** 那是他的电脑,你能用,但拿不走。

**agent 是发现出来的,不是配置出来的。** 我们扫这台机器上有没有这些命令,扫到什么显示什么。装了新的,下次它报到时就出现;卸载了就消失。

机器主人可以给每个已发现的 agent 起名字。名字属于这台机器上的这一个安装,不改变它是 Claude Code 还是 Codex,也不要求在 Space 里唯一;改名后,它在主人所属的每个 Space 里都显示同一个名字。暂时卸载再装回来,名字仍在。

### ⑤ 接完就不用管了

`connect` 一条命令做完全部,**包括让它以后自己在**。

|          | 笔记本   | 服务器 |
| -------- | -------- | ------ |
| 退出终端 | 还在     | 还在   |
| 关机     | 停       | —      |
| 重新登录 | 自动回来 | —      |
| 开机     | 不启动   | 启动   |

**笔记本合上盖子就该停,服务器开机就该在。** 这两种不同的期待不需要任何设置 —— 用什么身份跑 `connect`,就决定了是哪一种。

### ⑥ 掉线和回来

关掉服务,机器**变成离线,不是消失**。

> `mina-mbp` 离线 · 最后一次报到 3 分钟前

**干净地停下是立刻离线的** —— 它走之前会说一声。断网、崩溃、拔电源才需要等一会儿才看得出来。**常见的那种情况准确,意外那种才靠猜。**

再跑起来就回到在线,**不用重新批准**。机器记得自己是谁。

### ⑦ 拔掉

能从 Space 里移除一台机器。移除之后它的凭据立刻失效,那台机器上的服务会说自己被移除了然后退出。

## 服务器上怎么办

没有浏览器的机器走另一条路:在网页上先生成一把钥匙,再带着它跑。

```
sudo handover connect --key hk_…
```

**这不是另一套机制。** 网页上生成的钥匙,就是一条**已经批准过的**接入请求 —— 少的正好是③那一步。

|                    | 笔记本          | 服务器             |
| ------------------ | --------------- | ------------------ |
| 谁发起             | 命令行          | 网页               |
| 谁批准             | 人,在任意设备上 | 生成的那一刻就批了 |
| 钥匙什么时候看得见 | 不需要看见      | 只显示一次         |

**只显示一次**:关掉就再也看不到,只能重新生成一把。存下来的是它的哈希,我们自己也读不出来。

## 机器的身份

**机器不是人。** 它的凭据和人的凭据是两回事,一台机器拿到的东西打不开浏览器那扇门。

**一台机器属于连它的那个人,不属于 Space。** 它是你的笔记本 —— 笔记本归你,而你在几个 Space 里
是另一回事。反过来绑,「我想在另一个 Space 里用我自己的电脑」就得再接一次,那说不通。

**但这只说对了笔记本那一半。** 团队那台构建服务器不是谁的笔记本 —— 它是 Kai 接进来的,于是按上面
这条它就是 Kai 的,Kai 一走全队都用不了。这一片**只做「属于人」的那一半**,而这里先给另一半留个
位置:**以后要有一种机器不属于任何人,属于这个 Space 或这个部署。**

留位置不是留 TODO。它的意思是:**看到「机器的主人」时,不要假设那一定是一个人** —— 那个位置早晚
会被一个不是人的东西占上。

Tailscale 和 Devin Outposts 都分了这两种,而且 Tailscale 明说过反面:
「把一台提供服务的设备挂在某个人名下,删掉那个人你就失去那台设备。」

**它在哪些 Space 里能用,是从成员资格跟着走的,不是存下来的一份名单。**

```
你加入一个新 Space   → 你的机器自动在那儿
你离开一个 Space     → 自动不在了
```

不存,是因为存下来的那份就是「谁在哪个 Space」的第二份拷贝,而它和真的那份不一致的那天,
没有任何东西会说一声。

**只有主人能断开它。** 和你同一个 Space 的人能用你的笔记本 —— Space 就是干这个的 —— 但那还是
你的笔记本,能断开它就等于能拿走它。所以别人机器那一行上**没有那个按钮**,而不是有一个按了会失败的。

**每一行都写着是谁的。** 一个有两个人的 Space 里就有两台别人的笔记本,而 agent 在上面干的活,
动的是那个人的文件 —— 光有个名字说不出这件事。

**名字是机器自己报的**,默认是主机名,可改。名字不是身份,凭据才是,所以同名不冲突、也不拦着接入。

唯一按名字找机器的地方是 agent 之间的交办(`--to codex@mbp`,见 04)。**同一个 Space 里真有两台
`mbp` 的时候,先接进来的那台赢** —— 定死一个,同一个名字每次都指同一台,而不是看数据库先返回谁。
真到了要指名道姓分开它们的那天再说,现在两个人各自的笔记本重名,大概率不是问题。

## 失败与恢复

**接入**

| 发生什么          | 看到什么          | 能做什么       |
| ----------------- | ----------------- | -------------- |
| 码输错了          | 没有这个码        | 看一眼终端再输 |
| 码过期了(15 分钟) | 这个码已经过期    | 终端上重跑一次 |
| 人拒绝了          | 已拒绝,什么都没变 | 重来           |
| 已经被用掉了      | 这个码用过了      | 重来           |
| 钥匙不对 / 已撤销 | 这把钥匙不能用    | 换一把         |

**运行中**

| 发生什么            | 看到什么                            | 能做什么                    |
| ------------------- | ----------------------------------- | --------------------------- |
| 网断了              | 终端说在重连;网页上一段时间后转离线 | 什么都不用做,回来就自动接上 |
| 机器被移除了        | 终端说被移除了,然后退出             | 重新接入                    |
| 一个 agent 都没扫到 | 已接入,但**没有可用的 agent**       | 装一个,不用重新接入         |
| 凭据过期            | 终端说要重新接入                    | 重跑一次                    |

**「已接入但没有 agent」和「没接入」不能合并**:前者说明命令跑通了、网络通了、批准生效了,只差装一个 agent。合并成一个错误会让人去重接一台已经接好的机器。

## 承诺

```
① 没批准的机器什么都不是:不占名字、不出现、不能读
② 机器的凭据打不开浏览器那扇门,人的凭据也当不了机器
③ 批准在任意一台设备上都能做,和跑命令的机器在哪无关
④ 掉线是掉线,不是消失。回来不用重新批准
⑤ 生成的钥匙只显示一次,之后连我们也读不出来
⑥ agent 是发现出来的:装了就有,卸了就没;主人起的名字不被下一次发现覆盖
⑦ 移除一台机器,它的凭据立刻失效
⑧ 接一次就不用再管:笔记本跟着你登录走,服务器跟着开机走
```

## 完成标准

```
笔记本上跑一次,在手机上批准,机器出现在 Space 里
网页上生成钥匙,在一台没有浏览器的机器上接入,不需要批准
关掉命令 → 离线;再跑起来 → 在线,没有重新批准
装一个新 agent → 下次报到时出现;改名 → 每个 Space 一致;卸载再装 → 名字仍在
一个 agent 都没有的机器:接得上,并且说清缺什么
码过期、输错、被拒绝、已用过 → 四种各自说自己那句
移除机器 → 那边的命令自己退出
一把钥匙用过之后再用 → 拒绝
机器的凭据拿去调 /me → 拒绝
笔记本上接完关掉终端 → 还在线;重启电脑 → 离线;重新登录 → 自己回来
服务器上接完重启 → 自己回来
干净停止 → 立刻离线,不用等
```
