# 机器与 agent

一条完整的纵向:**Space 是空的 → 接一台机器 → 它出现在里面,带着它有的 agent**。

还不跑任何东西。这一片的终点是**能接上、能看到、能拔掉**。

**本文件不定布局。** 只写用户能做什么、被告知什么、失败时怎么办。

---

## 旅程

### ① 空 Space 说自己缺什么

进到一个还没有机器的 Space,看到的不是空白,是一句话和一条命令:

> 这里还不能跑任何东西。Agent 跑在**你的**机器上,不在我们这。

**为什么是你的机器,要在他跑命令之前说。** 他即将在自己的电脑上执行一串东西,得先知道那串东西是干嘛的。

### ② 接一台机器

```
handover connect
```

命令打印一个短码和一个网址:

```
在任意一台能开浏览器的设备上打开   https://…/connect
输入这个码                        WDJB-MJHT

或者直接打开                      https://…/connect/WDJB-MJHT
```

**"任意一台设备"是这句话的重点。** 跑命令的机器可能是一台没有浏览器的服务器,而批准这件事和它在哪台机器上无关。

两行都给,因为两种情况都真实存在:**能从终端复制的时候点第二行,拿手机对着服务器屏幕的时候念第一行的八个字符。** 但第一行是主路径 —— 只给长网址的话,输错一个字符得到的是找不到页面,而不是「这个码不对」。

码里**没有数字也没有元音**,所以不会有 `0` 和 `O` 的问题,也不会随机拼出一个词。

### ③ 批准

浏览器上看到的是**这台机器自称是什么**,由你决定它进哪个 Space:

> `mina-mbp` 想接进来。这是你刚才敲命令的那台吗?接进 **Acme**。

**机器不报自己要进哪个 Space,是批准的人选。** 机器没有立场选,而批准的人除了立场什么都有 ——
而且让机器报的话,一个没登录的人拿 slug 挨个试,就能从答案里分辨出哪个 Space 存在。

批准之后,终端那边自己就好了,不用回去粘任何东西。

**没批准之前它什么都不是。** 不占名字、不出现在列表里、不能读任何东西。

### ④ 看到它

Space 里出现这台机器:名字、在线、以及**它上面有哪些 agent**。

```
mina-mbp        在线
  Claude Code   2.1.4
  Codex         0.9.0
```

**agent 是发现出来的,不是配置出来的。** 我们扫这台机器上有没有这些命令,扫到什么显示什么。装了新的,下次它报到时就出现;卸载了就消失。

### ⑤ 接完就不用管了

`connect` 一条命令做完全部,**包括让它以后自己在**。

|          | 笔记本   | 服务器 |
| -------- | -------- | ------ |
| 退出终端 | 还在     | 还在   |
| 关机     | 停       | —      |
| 重新登录 | 自动回来 | —      |
| 开机     | 不启动   | 启动   |

**笔记本合上盖子就该停,服务器开机就该在。** 这两种不同的期待不需要任何设置 —— 用什么身份跑 `connect`,就决定了是哪一种。

### ⑥ 掉线和回来

关掉服务,机器**变成离线,不是消失**。

> `mina-mbp` 离线 · 最后一次报到 3 分钟前

**干净地停下是立刻离线的** —— 它走之前会说一声。断网、崩溃、拔电源才需要等一会儿才看得出来。**常见的那种情况准确,意外那种才靠猜。**

再跑起来就回到在线,**不用重新批准**。机器记得自己是谁。

### ⑦ 拔掉

能从 Space 里移除一台机器。移除之后它的凭据立刻失效,那台机器上的服务会说自己被移除了然后退出。

## 服务器上怎么办

没有浏览器的机器走另一条路:在网页上先生成一把钥匙,再带着它跑。

```
sudo handover connect --key hk_…
```

**这不是另一套机制。** 网页上生成的钥匙,就是一条**已经批准过的**接入请求 —— 少的正好是③那一步。

|                    | 笔记本          | 服务器             |
| ------------------ | --------------- | ------------------ |
| 谁发起             | 命令行          | 网页               |
| 谁批准             | 人,在任意设备上 | 生成的那一刻就批了 |
| 钥匙什么时候看得见 | 不需要看见      | 只显示一次         |

**只显示一次**:关掉就再也看不到,只能重新生成一把。存下来的是它的哈希,我们自己也读不出来。

## 机器的身份

**机器不是人。** 它的凭据和人的凭据是两回事,一台机器拿到的东西打不开浏览器那扇门。

**一台机器属于一个 Space。** 不做「一次接入,所有 Space 都能用」——能进所有 Space 的机器,丢一台就是丢全部。同一台电脑要进两个 Space,就接两次。

**名字是机器自己报的**,默认是主机名,可改。名字只是给人看的,不是身份 —— 两台机器同名不影响任何事。

## 失败与恢复

**接入**

| 发生什么          | 看到什么          | 能做什么       |
| ----------------- | ----------------- | -------------- |
| 码输错了          | 没有这个码        | 看一眼终端再输 |
| 码过期了(15 分钟) | 这个码已经过期    | 终端上重跑一次 |
| 人拒绝了          | 已拒绝,什么都没变 | 重来           |
| 已经被用掉了      | 这个码用过了      | 重来           |
| 钥匙不对 / 已撤销 | 这把钥匙不能用    | 换一把         |

**运行中**

| 发生什么            | 看到什么                            | 能做什么                    |
| ------------------- | ----------------------------------- | --------------------------- |
| 网断了              | 终端说在重连;网页上一段时间后转离线 | 什么都不用做,回来就自动接上 |
| 机器被移除了        | 终端说被移除了,然后退出             | 重新接入                    |
| 一个 agent 都没扫到 | 已接入,但**没有可用的 agent**       | 装一个,不用重新接入         |
| 凭据过期            | 终端说要重新接入                    | 重跑一次                    |

**「已接入但没有 agent」和「没接入」不能合并**:前者说明命令跑通了、网络通了、批准生效了,只差装一个 agent。合并成一个错误会让人去重接一台已经接好的机器。

## 承诺

```
① 没批准的机器什么都不是:不占名字、不出现、不能读
② 机器的凭据打不开浏览器那扇门,人的凭据也当不了机器
③ 批准在任意一台设备上都能做,和跑命令的机器在哪无关
④ 掉线是掉线,不是消失。回来不用重新批准
⑤ 生成的钥匙只显示一次,之后连我们也读不出来
⑥ agent 是发现出来的:装了就有,卸了就没,不用改配置
⑦ 移除一台机器,它的凭据立刻失效
⑧ 接一次就不用再管:笔记本跟着你登录走,服务器跟着开机走
```

## 完成标准

```
笔记本上跑一次,在手机上批准,机器出现在 Space 里
网页上生成钥匙,在一台没有浏览器的机器上接入,不需要批准
关掉命令 → 离线;再跑起来 → 在线,没有重新批准
装一个新 agent → 下次报到时出现;卸载 → 消失
一个 agent 都没有的机器:接得上,并且说清缺什么
码过期、输错、被拒绝、已用过 → 四种各自说自己那句
移除机器 → 那边的命令自己退出
一把钥匙用过之后再用 → 拒绝
机器的凭据拿去调 /me → 拒绝
笔记本上接完关掉终端 → 还在线;重启电脑 → 离线;重新登录 → 自己回来
服务器上接完重启 → 自己回来
干净停止 → 立刻离线,不用等
```
