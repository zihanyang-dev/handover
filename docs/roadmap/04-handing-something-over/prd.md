# 把一件事交出去

`03` 的终点是**你陪着它做**。这一片的终点是**你交给它,然后走开**。

一条完整的纵向:**聊清楚 → 交出去 → 它自己往下走 → 卡住了来找你 → 半夜看一眼、发现偏了就说一句 → 做完了告诉你**。

**本文件不定布局。** 只写用户能做什么、被告知什么、失败时怎么办。

---

## 交办不是新建,是一个开关

```
03 的对话     一轮做完,它停下来等你说下一句
04 的一件事   一轮做完,它自己决定下一步
```

**同一段对话,同一个 agent,同一个目录。** 区别只在你走不走开。

所以没有「新建任务」这个动作。你聊了五句摸清楚了,说一句「行,剩下的你自己做」,它就接着往下走 —— 这是一个开关,把它做成一次创建等于让人把刚才聊的东西再说一遍。

---

## 旅程

### ① 聊清楚,然后交出去

一段普通对话。你问、它答、你补充。摸清楚之后,交给它。

**你要说的只有一句话:你要它做成什么。** 前面聊的它都还记得 —— 那本来就是同一段对话。

从这一刻起,这段对话有了三样东西:**一个目标、一个状态、一个在等的人(你)**。

### ② 它自己往下走

它做一步、写一步,和 `03` 一模一样:说了什么、读了什么、跑了什么,一件一行。**这不是另一种视图,就是同一段对话继续往下滚。**

不一样的是:一轮做完它不停下来。它自己决定下一步是接着做、还是需要点别的什么。

### ③ 三种「在等」

它停下来的时候,永远是在等三样东西之一:

```
等你       它问了你一件事,没有你的答复走不下去
等子任务   它把一块活交给了另一个 agent
等一个时刻 「明天 12:00 再看一眼上线有没有异常」
```

**每一种都有两个醒法:它等的那件事发生了,或者你说话了。**

所以「我想插一句」永远不需要特殊设计 —— 不管它在等什么,你打一句话它就醒。

### ④ Inbox:所有在等你的事

首页一个 Inbox,**跨所有 Space**。里面是所有「在等你」的事,一行一件,说清楚它在问什么。

点进去就是那段对话。打一句话回它,它就继续。

**这是这个产品唯一的刹车,所以它必须准。** 一件在等你的事不出现在这里,就是一件永远不会再动的事。

### ⑤ 半夜爬起来看一眼

打开那件事,从头往下滚,它做过的每一步都在。

发现它偏了 —— **直接说话。说话就是打断**(`03` ⑩)。它当场停下来听你这句,然后带着这句继续往下走。

**如果它当时正在等一个子任务**,你说的话一样把它叫醒。要不要把那个子任务也停掉,由它判断 —— 它知道你这句话有没有让那块活失去意义。你也可以自己进去停。

### ⑥ 它可以把一块活交给别人

它自己开一件子任务:一个目标、一个 agent、一台机器。可以是别的 agent、别的厂商。

**子任务也是一段对话,结构和上面完全一样。** 唯一的区别是:**它的负责人不是你,是那个开它的 agent。** 所以子任务问问题不会跑到你的 Inbox 里 —— 它去问开它的那个 agent。

你在一件事的页面上看得到「它开了这几件事」,点进去就是那几段对话,你能看、也能停。

**交付物就是子任务结束时说的那句话。** 「三家的价格是 X Y Z」够了;改了代码的就说「在 `sub/xxx` 这个分支上」,然后**父 agent 自己 merge**。合不上它就说合不上 —— 那就落回「在等你」。

**一台机器一次只干一件事。** 想同时干两件,子任务就得开在别的机器上;同一台就排队。

**永远不做:多个 agent 同时做同一件事。**

### ⑦ 等一个时刻

「三小时内每十分钟看一下数据,三天后再看一次转化,给我一份报告」——

它一次只等**一个**时刻。醒来、看一眼、自己决定下一个时刻是十分钟后还是三天后。**每次醒来它都能改主意** —— 第二十分钟数据就崩了,它不会傻等到第三小时。

「每周五帮我调研一下竞品」是同一个机制:醒来、做、再设下周五。这样的事没有终点,它就一直在那儿等着,直到你收回。

### ⑧ 做完了

它说做完了,或者说做不了 —— 两种都是结束,都带一句话说清楚。

**结束就是真的结束。** 你再说话,它就是一段普通对话了。想让它再自己跑,再交办一次。

### ⑨ 你随时能收回

「停,我自己来。」它变回一段普通对话,你接着聊。**已经做的都在**,收回不是丢弃。

## 一件事

```
目标        你交办时说的那句话
一个 agent  就是这段对话本来那个。换 agent = 换一件事
一台机器    就是这段对话本来那台,同一个目录
状态        在做 / 在等(等你·等子任务·等一个时刻)/ 完了
负责人      你,或者开它的那个 agent
子任务      它自己开的,一层套一层
```

**没有第二条时间线。** 它做了什么、你说了什么,还是那一段对话,按顺序。

**一件事底下同时最多四个 agent 在干活。** 整棵树共享这一个数 —— 开一件子任务就占一个位置,子任务自己再开也从同一个数里拿。一个数把宽度和深度一起管住了。v1 不给你调:现在没人知道多少合适,给一个旋钮等于把这个问题推给用户。

## 失败与恢复

**它自己走不下去的时候**

| 发生什么       | 看到什么           | 谁来接                 |
| -------------- | ------------------ | ---------------------- |
| 一轮失败了     | 失败的原因         | **你** —— 进「在等你」 |
| 它说做不了     | 它自己的话         | 结束,不用你做什么      |
| 常驻进程被杀了 | 那一轮「不知道」   | **你** —— 进「在等你」 |
| 它的机器不在了 | 「它的机器不在了」 | 等机器回来 / 收回      |

**一轮失败之后它不自己重试。** 再往下走需要有人判断这次失败要不要紧,而那个人是你。一个自己重试到成功为止的 agent,是一个没人知道它试了多少次的 agent。

**子任务出事的时候**

| 发生什么           | 父任务看到什么                       |
| ------------------ | ------------------------------------ |
| 子任务说做不了     | 它说不了的原因,由父 agent 决定怎么办 |
| 子任务的机器不在了 | 「你等的那件事的机器不在了」         |
| 你把子任务停了     | 「它被停了」                         |

三种都是**把父任务叫醒**,让它自己判断 —— 我们不替它决定要不要换个做法。

**你那边**

| 发生什么         | 会怎么样                                 |
| ---------------- | ---------------------------------------- |
| 你关了浏览器     | 它照跑                                   |
| 你几天没看 Inbox | 它就在那儿等着,不会超时,也不会自己往下猜 |

## 承诺

```
① 交办不需要你重说一遍。它记得你们刚才聊的,因为那就是同一段对话
② 它停下来的时候,你永远知道它在等什么 —— 等你、等子任务、还是等一个时刻
③ 不管它在等什么,你说一句话它就醒
④ 它做的每一步你都看得见,和你陪着它的时候一模一样
⑤ 在等你的事全在一个 Inbox 里,跨 Space。不在那里 = 不存在
⑥ 一轮失败它不自己重试,来问你
⑦ 子任务的问题不会跑到你面前 —— 它去问开它的那个 agent
⑧ 你随时能收回,已经做的都在
⑨ 一台机器一次只干一件事,两个 agent 不会在一个目录里互相踩
⑩ 做完了就是做完了。没有一件事会悄悄地又开始动
```

**这一片没有预算,也没有上限。** 唯一的刹车是你,和你手上的 Inbox。

这是一个明知代价的选择:一个每一轮都「成功」却在原地转圈的 agent,没有任何东西会拦它。我们拿承诺④换 —— 它做的每一步你都看得见,所以你半夜看一眼就发现了。**上限要么记得准,要么就是一个让人以为有人在看着的假象**,而我们现在还不知道该记什么。

## 完成标准

```
聊三句,然后交办 → 它接着往下走,不用你再说什么
它做的每一步都在那段对话里,和交办前长得一样
它问你一件事 → 出现在 Inbox 里,回一句它就继续
关掉浏览器,过一小时回来 → 它做的都在
它在干活的时候说一句话 → 当场打断,带着这句继续
它在等子任务的时候说一句话 → 一样叫醒它
它设一个两分钟后的时刻 → 两分钟后它自己醒,接着做
它开一件子任务给另一台机器上的 codex → 两段对话都看得见,子任务问问题不进你的 Inbox
子任务说做完了 → 父任务当场醒,拿到它说的那句话
子任务的机器拔网线 → 父任务被告知,而不是永远等下去
同一台机器上开第二件子任务 → 排队,不是并行
一轮跑失败 → 进「在等你」,它没有自己重试
杀掉常驻进程再拉起来 → 那一轮「不知道」,那件事在等你,而不是自己接着跑
收回 → 变回普通对话,已经做的都在
做完了之后再说话 → 就是普通对话,它不会自己又动起来
```
