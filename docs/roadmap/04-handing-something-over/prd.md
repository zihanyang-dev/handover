# 把一件事交出去

`03` 的终点是**你陪着它做**。这一片的终点是**你交给它,然后走开**。

一条完整的纵向:**聊清楚 → 它复述,你点头 → 它自己往下走 → 卡住了来找你 → 半夜看一眼、
发现偏了就说一句 → 做完了给你一份东西**。

**本文件不定视觉。** 写用户能做什么、被告知什么、失败时怎么办,以及**什么信息放在哪一块** ——
最后这件事是产品决定,不是设计稿。

---

## 交办不是新建,是一个开关

```
03 的对话     一轮做完,它停下来等你说下一句
04 的一件事   一轮做完,它自己决定下一步
```

**同一段对话,同一个 agent,同一台机器,同一个目录。** 区别只在你走不走开。

所以没有「新建任务」这个动作。你聊了五句摸清楚了,说一句「行,剩下的你自己做」—— 把这做成
一次创建,等于让人把刚聊完的东西再打一遍。

---

## 旅程

### ① 聊清楚,然后它复述一张卡片

一段普通对话。你问、它答、你补充。摸清楚之后,**按「交给它」**。

(你直接打「剩下的你自己做」也可能有用,但那要看那个 agent 碰巧知不知道这回事 ——
**按钮是唯一保证走得通的入口**,它替你把话问清楚。)

**它不会立刻开跑,它先复述:**

```
我要做成的是
把 client.ts 里写死的 30 秒超时改成可配置,默认还是 30 秒,加一个测试

zane-mbp · ~/Dev/carry

                      [交给它]
     不对的话就接着说,什么都还没开始
```

**这张卡片不是审批,是复述。你确认的不是「准不准」,是「你听懂了吗」。**

**只有一个按钮。** 早先画的是 `[交给它] [不对,我再说说]`,而第二个按钮只能把卡片收起来 ——
那要存一个「已经忽略过」的状态,为一件本来就不用记的事。不同意就是接着说话,那是对话本来的样子,
说清楚就够了。

两个理由:

- **目标得是一句确定的话** —— 列表里显示它、Inbox 里显示它、三天后回来还是它。而「行,剩下的
  你自己做」不是目标。**这句话该由要干活的那个来写**,它一写你就必然要看一眼。
- **这是唯一一次十秒钟能纠偏的机会。** 过了这个点,下一次纠偏是你半夜爬起来发现它跑偏了三小时。

卡片上只有一句目标和一行位置。**没有计划、没有步骤、没有预估。**

### ② 它自己往下走

它做一步、写一步,和 `03` 一模一样。**不是另一种视图,就是那段对话继续往下滚。**

不一样的是:一轮做完它不停下来,它自己决定下一步。

### ③ 它自己停下来,只有两种

```
在等你    它问了你一件事,没有你的答复走不下去
在睡      「明天 12:00 再看一眼数据」
```

**两种都被你说话叫醒。** 不管它在等什么、睡到什么时候,你打一句话它当场就醒 ——
所以「我想插一句」永远不需要特殊设计。

它**在跑**的时候不一样:那时候你要先按停止(`03` ⑩)。「发送」永远不会毁掉一轮。

**「在等子任务」不是一种停法。** 它开出去的活还没完,那是它孩子的事;页面上写着,但它不是这件
事的状态。

### ④ Inbox:所有在等你的事

首页一个 Inbox,**跨所有 Space**。一行 = 一个目标 + 它问你的那句话。

点进去就是那段对话,打一句话回它,它就继续。

**这是这个产品唯一的刹车,所以它必须准。** 一件在等你的事不出现在这里,就是一件永远不会再动的事。

### ⑤ 半夜爬起来看一眼

打开那件事。**右边那块是给这一眼准备的:**

```
目标 · 现在什么状态 · 在哪台机器的哪个目录
大事记      你交给它 02:14 · 开了一件活 02:31 · 问了你一次 03:02 · 在跑
它开的活    补一个集成测试   Codex · build-server-1 · 在跑
产出        上线后三天数据复盘
```

**大事记就是进度。** 这几条系统自己全知道 —— 交给它、开了活、子任务回话了、问了你、睡了、
完了、你收回了 —— **不用 agent 额外写一个字**,它调那几条命令的时候就顺手记下了。
点一条跳到时间线上那个位置。

左边那条线是细节:它读了什么、跑了什么。**中间连续的工具调用会折起来**,不然大事全被淹没。

发现它偏了 —— **按停止,它停下来,你再说**(`03` ⑩)。它带着你这句继续往下走。

**不管它在跑、在等你、还是在睡,那个按钮和那个输入框都在。** 睡着的时候你说一句话,它当场就醒。

### ⑥ 它可以把一块活交给别人

它自己开一件子任务:一个目标、一个 agent、一台机器。可以是别的 agent、别的厂商。

**子任务也是一段对话,结构完全一样。** 唯一的区别:**它的负责人不是你,是开它的那个 agent。**
所以子任务问问题不会跑到你的 Inbox 里,它去问开它的那个。

```
右边「它开的活」   点进去 = 那段对话
子任务顶上一行     属于 ⟨父任务的目标⟩ ↑
```

**交付物就是子任务结束时说的那句话。** 「三家的价格是 X Y Z」够了;改了代码的就说「在
`sub/xxx` 这个分支上」,然后**父 agent 自己合**。合不上它就说合不上 —— 那就落回「在等你」。

**一台机器一次只干一件事。** 所以想让两件活**同时在跑**,它们得在两台机器上;落在同一台就排队,
一件一件来。

**永远不做:多个 agent 同时做同一件事。**

### ⑦ 睡到某个时刻

「三小时内每十分钟看一下数据,三天后再看一次转化,给我一份报告」——

它一次只睡**一个**时刻。醒来、看一眼、自己决定下一个时刻是十分钟后还是三天后。
**每次醒来它都能改主意** —— 第二十分钟数据就崩了,它不会傻等到第三小时。

「每周五帮我调研竞品」是同一个机制:醒来、做、再设下周五。这样的事没有终点,一直在那儿睡着,
直到你收回。

### ⑧ 产出

它顺手改的文件不叫产出 —— 想看改了什么,`git diff` 就在那台机器上。

**产出是它专门写出来的一件东西,有标题。** 一份复盘报告、一份调研、一份迁移方案。它写完就
挂在右边,你点开就能看,不用从两百行里往回翻。

**我们只放它自己说是产出的东西。** 从它跑过的命令里猜「它改了哪些文件」,是我们替它编结论 ——
这个产品别处都不这么干。

### ⑨ 做完了,或者你收回

它说做完了、或者说做不了,都带一句话说清楚。你也可以随时收回。

**收回一件事,连它开出去的活一起收回。** 你按收回是因为「剩下的我自己来」—— 而它开出去的活
还在别的机器上改代码,父任务又再也不会去读那个结果了。留着它跑,就是一个没人看着、也没人要的
agent 在动你的仓库。

**三种都是真的结束。** 你再说话,它就是一段普通对话了。想让它再自己跑,再交办一次。

**列表上只写「完了」,不贴「成/败」的标签。** 怎么完的以它自己说的那句话为准 —— 点进去就看到,
而一个我们替它下的结论,会把「因为一次网络抖动而没做完」和「它判断这事做不成」写成同一个词。

## 一件事

```
目标        它复述、你点头的那句话
一个 agent  就是这段对话本来那个。换 agent = 换一件事
一台机器    就是这段对话本来那台,同一个目录
状态        在跑 / 在等你 / 在睡 / 完了
负责人      你,或者开它的那个 agent
子任务      它自己开的,一层套一层
产出        它专门写出来的东西
```

**没有第二条时间线。** 它做了什么、你说了什么,还是那一段对话,按顺序。

**一段对话同时只能有一件没完的事。** 但一段对话可以**先后**有好几件 —— 它修完了 bug,你们又
聊两句,你再交办「盯三天数据」。那是第二件事,它还记得第一件是怎么修的。

**子任务的数量没有上限,因为已经有一个物理的了:一台机器一次只干一件事。** 同时在跑的 agent
数量顶天就是你接进来的机器数 —— 再凭空定一个「最多四个」,防的是一件已经被物理拦住的事,
而执行它要在每次开活时数一遍整棵树。**说不出疼在哪的规则就不该存在。**

开出去一百件排队的活当然还是可能的。那种时候你半夜看一眼右边就发现了 —— 和「没有上限」是
同一个选择,拿看得见换。

## 什么信息放在哪一块

```
左边一条线   它一步一步在干什么 —— 量大,一次性,过了就过了
右边一块     这件事 —— 量少,永远重要
```

**大事必然被细节淹掉,所以它们不能在同一个地方找。**

```
右边:目标 · 状态 · 在哪跑
      大事记        点一条跳到线上
      它开的活      子任务的入口,一直在
      产出          点开就看
```

**右边这块只在交办之后出现。它出现,就是「你放手了」在页面上的样子。**

## 失败与恢复

**它自己走不下去的时候**

| 发生什么       | 看到什么           | 谁来接                 |
| -------------- | ------------------ | ---------------------- |
| 一轮失败了     | 失败的原因         | **你** —— 进「在等你」 |
| 它说做不了     | 它自己的话         | 结束,不用你做什么      |
| 常驻进程被杀了 | 那一轮「不知道」   | **你** —— 进「在等你」 |
| 它的机器不在了 | 「它的机器不在了」 | 等机器回来 / 收回      |

**一轮失败之后它不自己重试。** 再往下走需要有人判断这次失败要不要紧,而那个人是你。一个自己
重试到成功为止的 agent,是一个没人知道它试了多少次的 agent。

**子任务出事的时候**

| 发生什么           | 父任务看到什么                       |
| ------------------ | ------------------------------------ |
| 子任务说做不了     | 它说不了的原因,由父 agent 决定怎么办 |
| 子任务的机器不在了 | 「你等的那件事的机器不在了」         |
| 你把子任务停了     | 「它被停了」                         |

三种都是**把父任务叫醒**,让它自己判断 —— 我们不替它决定要不要换个做法。

**你那边**

| 发生什么         | 会怎么样                             |
| ---------------- | ------------------------------------ |
| 你关了浏览器     | 它照跑。回来一条不少                 |
| 你几天没看 Inbox | 它就在那儿等着,不超时,也不自己往下猜 |

**你不在的时候少的只有一样:「它当时在想什么」。** 那东西本来也没人回去翻 —— 见 `03` ⑦ 那张
对照表,这一片一个字没改。

## 承诺

```
① 交办不用你重说一遍。它记得你们刚才聊的,因为那就是同一段对话
② 它开跑之前先复述一遍,你看一眼再点头
③ 它停下来的时候,你永远知道它在等什么 —— 等你,还是在睡
④ 它在等你或者在睡,你说一句话它就醒;它在跑,按停止它才停
⑤ 它做的每一步你都看得见,和你陪着它的时候一模一样
⑥ 大事和细节分开放 —— 大事不会被两百行工具调用淹掉
⑦ 在等你的事全在一个 Inbox 里,跨 Space。不在那里 = 不存在
⑧ 一轮失败它不自己重试,来问你
⑨ 子任务的问题不会跑到你面前 —— 它去问开它的那个 agent
⑩ 产出只放它自己说是产出的,我们不从它跑过的命令里猜
⑪ 你随时能收回,连它开出去的活一起停。已经做的都在
⑫ 一台机器一次只干一件事,两个 agent 不会在一个目录里互相踩 —— 这也是同时在跑的
  agent 数量的上限,不用另外定一个
⑬ 做完了就是做完了。没有一件事会悄悄地又开始动
```

**这一片没有预算,也没有上限。** 唯一的刹车是你,和你手上的 Inbox。

这是一个明知代价的选择:一个每一轮都「成功」却在原地转圈的 agent,没有任何东西会拦它。我们拿
承诺⑤⑥换 —— 它做的每一步你都看得见,而且大事就在右边那一块里,你半夜扫一眼就发现了。
**上限要么记得准,要么就是一个让人以为有人在看着的假象**,而我们现在还不知道该记什么。

## 完成标准

```
聊三句,说「你自己做吧」→ 它复述一张卡片,不是直接开跑
点「交给它」→ 它接着往下走,不用你再说什么;没有第二段对话被建出来
不点那个按钮、直接继续说话 → 什么都没开始,接着聊(**没有「不对」按钮**:不同意就是接着聊)
它做的每一步都在那段对话里,和交办前长得一样
连着十几个工具调用 → 折起来,大事没被淹掉
右边:目标 · 状态 · 大事记 · 它开的活 · 产出
点大事记里一条 → 跳到时间线上那个位置
它问你一件事 → 出现在 Inbox 里,回一句它就继续
关掉浏览器,过一小时回来 → 它做的都在,实时流当场接上
它在干活的时候说一句话 → 当场打断,带着这句继续
它在睡的时候说一句话 → 一样叫醒它
它设一个两分钟后的时刻 → 两分钟后它自己醒,接着做
它开一件子任务给另一台机器上的 codex → 右边点得进去,子任务顶上有回来的路
它连开三件子任务 → 都开得出来,不被任何数量上限拦住
子任务问问题 → 不进你的 Inbox
子任务说做完了 → 父任务当场醒,拿到它说的那句话
子任务的机器拔网线 → 父任务被告知,而不是永远等下去
同一台机器上开第二件子任务 → 排队,不是并行
它写一份产出 → 右边挂着,点开能看
一轮跑失败 → 进「在等你」,它没有自己重试
杀掉常驻进程再拉起来 → 那一轮「不知道」,那件事在等你,而不是自己接着跑
收回 → 变回普通对话,已经做的都在;它开出去还没完的活也一起停了
做完了之后再说话 → 就是普通对话,它不会自己又动起来
做完了之后再交办一次 → 第二件事,它还记得第一件
```

## 不在这一片

```
一个 task 一个目录        要解决的是「一台机器同时干几件事」。而适配「升级一段对话」的那个
(worktree 隔离)          做法是把一个跑了五轮的 agent 搬进新目录 —— 它记忆里全是旧的绝对
                          路径,照旧路径读得到,于是它以为在自己的树里,实际在改主干。
                          先用「一台机器一次一件事」,隔离等一个不搬动它的做法

预算 / 上限               不知道该记什么之前,一个记不准的上限比没有更坏

计划 / 动态 workflow      「人能看到 agent 的计划」是对的,但怎么设计还没想清楚。
                          现在看进度就是右边那块大事记 —— 而它不欠 agent 任何东西

从命令里猜它改了哪些文件    猜不准的东西不该占一个固定位置假装权威。git diff 就在那台机器上

多个 agent 做同一件事      永远不做

一件事换 agent            换 agent 就是换一件事,和一段对话换 agent 同一条规则

外部事件 / webhook        「等」的形状已经容得下第四种,缺的是一扇门:一个不认识的外部系统
                          怎么证明它只能敲这一件事。那是一块真活,不顺手做

给别人交办                这一片只有「我交给我的 agent」。人交给人是另一件事
```
