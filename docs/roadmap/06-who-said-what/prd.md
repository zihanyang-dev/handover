# 谁说的

`05` 的终点是**一个 Space 里有第二个人**。这一片的终点是**看得出哪句话是谁说的** ——
以及,两个人同时开口时,没有一句被悄悄吞掉。

## 为什么是现在

不是因为「多人协作还差个头像」,是因为**已经有一句承诺是假的,还有一个 bug 只在第二个人出现之后才露头**。

### 承诺的一半是假的

`05` ⑦ 写着:

> **他说过的话、他交办过的事,永远还写着他的名字。**

右半句做到了 —— `tasks.owner_user_id`,查得出名字。左半句没有:

```
messages   seq · role · content · ...
                  ↑ 'user' / 'assistant' / 'tool' / 'activity'
                    只说「是个人说的」,不说是哪个人
```

Kai 和 Mina 在一个 Space。Mina 点开一段对话,看到 `user: 把超时改成可配置` ——
**那可能是 Kai 说的,也可能是她自己上周说的,页面写不出来,因为库里就没存。**

### 一句话会被吞掉,而且不出声

量出来的,不是推的:

```
Kai   问「超时的配置在哪」        → 写进 transcript,seq 2
Mina  问「它会影响重试吗」        → 写进 transcript,seq 3

agent 实际被问到:  只有 Mina 那句
这一轮盖住的范围:  afterSeq = 3,把 seq 2 一并盖掉
```

**Kai 那句话永远不会被送给 agent,也永远不会被回答。**而它就在屏幕上,看起来像排着队。

取最后一句是为**一个人**写的,而且那时是对的:你打了两遍,当然答最新那遍。
第二个人一出现,同一条规则就变成丢消息。

### 加了名字,就必须同时堵一个洞

机器上报那条路收的是完整的消息联合,里面含 `role: 'user'`——
**agent 现在就能发一行读起来像人说的话。**

今天无所谓:每一行都没有名字,冒充谁都一样。
加上名字之后,它冒充的就是一个具体的人。**所以这两件事必须同一次做完。**

> **这一片目前没有屏幕。** 每行话上的人名和「谁在输入」都不显示。
> 前端重构只做到「登录 → 建 Space → 连机器 → 和 agent 说话」这一刀,这些屏幕还没重做。
> 服务端全部实现、全部有测试,只是浏览器上按不到。欠账清单在 `rules/reachable.spec.ts` 的
> `NO_SCREEN_YET`,它只允许变短。

## 旅程

### ① 每句话有名字

```
Kai   把超时改成可配置
      好,我看一下 client.ts …
Mina  ok,你接着做吧
```

agent 说的话不挂人名 —— 它是谁,这段对话顶上已经写着(`claude-code on kai-mbp`)。
工具调用和大事记也不挂:没有人说过它们。

**只有人说的话有名字。**[Slack 的模型就是这样:每条消息带 `user`,机器人带 `bot_id`](https://slack.com/help/articles/33076000248851-Work-with-AI-agents-in-Slack) ——
**作者是一个字段,不是一个角色。**

侧边栏的列表同理:每一段对话标出是谁开的。

### ② 两个人同时说,两句都被听见

一轮带走的是**上一轮结束之后所有人说过的话**,不是最后一句。

```
Kai   超时的配置在哪
Mina  它会影响重试吗
                        ← agent 这一轮同时看到这两句
```

[Slack 里两个人 @ 同一个 bot,bot 两句都收得到](https://slack.com/help/articles/33076000248851-Work-with-AI-agents-in-Slack)。
我们现在只收最后一句,那是一个人时代的规则。

**顺序就是 transcript 的顺序**,不重排、不合并、不去重 —— 它们本来就是先后说的。

### ③ 谁在输入,看得见

```
Mina 正在输入…
```

**不落库。**它和「它正在想什么」「命令刚打印了什么」是同一类东西:走 `03` 那条不落库的实时通道,
连接断了就没了,永远不进 transcript。

### ④ 不锁输入框

**任何时候两个人都能打字。**

[协同编辑这条路早走过一遍](https://systemdesignschool.io/problems/google-doc/solution):

> Pessimistic locking (where a user acquires an exclusive lock and others see a read-only view)
> is **completely incompatible with real-time collaboration**. If one person locks a document,
> others are essentially **frozen out**.

具体到我们:Kai 点开输入框去接了杯咖啡,Mina 五分钟按不了键;Kai 的标签页崩了,锁泄漏,
于是要有超时,而超时多久又是一个要定的数;「谁持有锁」是一个新状态,新状态要说清所有进边出边。

**而且它防不住真正丢消息的那件事** —— ② 里那两句是先后说的,不是同时说的,锁一点忙帮不上。
Google Docs 和 Confluence 给的答案是 presence,不是锁,我们照抄。

### ⑤ agent 不能冒充人

机器那条上报的路,只收 `assistant` / `tool` / `activity` 三种。
**人说的话只有人那条路能写,而那条路的名字来自会话,不来自 body。**

[Copilot 把不是它写的补全也标成了自己,被称作「AI 归属变成信任问题」](https://www.penligent.ai/hackinglabs/vs-code-copilot-co-author-when-ai-attribution-becomes-a-supply-chain-trust-problem/)。
一个能被伪造的名字,比没有名字更坏。

### ⑥ 更早以前的话,没有名字就说没有

这一片之前写下的行没有作者,**补不出来**。所以它们就显示成没有名字。

不按对话推断、不按「反正只有一个人」推断。同一件事上
[Copilot 猜错了归属](https://www.penligent.ai/hackinglabs/vs-code-copilot-co-author-when-ai-attribution-becomes-a-supply-chain-trust-problem/),
而我们本来就有一条硬规矩:**「不知道」永远不被猜成别的**(`03` ⑤)。

## 承诺

```
① 人说的每一句话都写着是谁说的,而且那个名字不可能是 agent 写上去的
② agent 说的话、工具调用、大事记都不挂人名 —— 没有人说过它们
③ 两个人在同一轮里说的话,两句都会被送到 agent 面前,按说的顺序
④ 谁正在输入,别人看得见 —— 而且这件事从不进 transcript
⑤ 任何时候谁都能打字。我们不锁输入框
⑥ 这一片之前的话没有名字,我们就说没有,不猜
⑦ 一段对话是谁开的,是从它第一句人话推出来的,不另外存一份
```

## 完成标准

```
Kai 说一句,Mina 打开这段对话        → 那一行写着 Kai
Mina 也说一句                       → 两行分别写着两个名字
agent 回一句                        → 不挂任何人的名字
两个人在同一轮里各说一句             → agent 这一轮同时收到两句,顺序和屏幕上一样
                                      两句都不会没人管
Mina 在输入                         → Kai 看到「Mina 正在输入…」
Mina 关掉页面                       → 那行提示消失,transcript 里没有留下任何东西
机器试着发一行 role: 'user'          → 被拒
这一片之前的旧对话                   → 人说的行显示成没有名字,页面不猜
侧边栏的对话列表                     → 每一行标出是谁开的
```

## 做的时候改了一条既有规则

**「机器不在时拒绝人说话」删掉了。**

原来 `sayTo` 里有一句:机器静默超过 55 秒就判定不在,这时候有人说话就返回 409,
**这句话根本不会被写下来**。

它是给「一个人对着自己的笔记本」写的 —— 那时候提前告诉你「你电脑睡了」比让你对着空气
说话好。**Space 里有第二个人之后,这条规则就是在丢消息**:Mina 不知道那是 Kai 的电脑,
也不知道他什么时候回来,她打完的一句话就这么没了。而这一片的完成标准写着「两句都不会
没人管」。

而且它拦的根本不是一次失败的投递 —— **这个系统里没有「发给机器」这个动作**。机器是自己
来问的(`owedATurn`),那条查询只要求机器**没有被移除**,不要求它在线。话写进 transcript
就在那儿等着,笔记本一开就带走。

三个参照,方向一致:

```
Multica          daemon 每 3 秒轮询 + WS 唤醒;daemon 离线时服务端存着,回来领走。无期限
GitHub Actions   指定给离线自托管 runner 的 job 进队列等着。排队超 24 小时取消
WhatsApp/Signal  发给离线的人的消息落盘,上线时投递。Signal 保留 30 天
```

**没有一个拒绝写入。** 期限那一条我们不抄:GitHub 和 Signal 的队列是投递缓冲,我们的
transcript 是记录 —— 话永久留着,等的是「那一轮」。笔记本永不回来,这件活可以转给别的
机器,那条路已经有了。Multica 也没有期限,理由一样。

页面不变:它本来就从 transcript 里读机器的在与不在,照旧显示「它的机器不在」。

## 不在这一片

```
锁输入框 / 编辑锁          见 ④。Google Docs 和 Confluence 都不锁,理由写在那儿
@ 某个人                   要有通知才有意义,而通知是 Inbox 的事;
                          现在 Inbox 只装「活在等你」,加「有人叫你」是另一片
改自己说过的话 / 撤回       transcript 是记录,发生过就不改(`架构` 3)
已读 / 谁看过              没有消费者。真有人问「他看到了吗」时再说
头像                       名字够用。上传图片要存储、要裁剪、要审核,全是这一片之外的东西
打断是谁干的               `sayTo` 里打字会掐掉在跑的那一轮。加了名字之后这一行本来就写得出
                          是谁,但「该不该让别人掐掉你的轮」是一个产品决定,单独说
```
