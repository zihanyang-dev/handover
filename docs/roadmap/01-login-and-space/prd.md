# 登录与 Space

一条完整的纵向:**打开 → 登录 → 选或建一个 Space → 进去 → 刷新还在**。

进去之后是空的。这一片的终点是**能进、能切、能退**。

**本文件不定布局。** 只写用户能做什么、被告知什么、失败时怎么办。

---

## 旅程

### ① 登录

用户能选:Google、GitHub、或者输邮箱要一个验证码。

**在他做选择之前**,必须已经知道这一句:

> 任何方式,只要邮箱相同,进的都是同一个账号。

这句话决定他敢不敢换一种方式点。放在他选完之后才说等于没说。

### ② 验证码

系统告诉他:

> 我们给 mina@example.com 发了一个六位码。五分钟内有效,只有最新一封有效。

- 输满六位**自动提交**,不用再确认一次
- 能重新发送,并且看得到还要等多少秒
- 能换一个邮箱,**换回去时原来输的地址还在**

### ③ 如果这次登录并入了一个已有账号

只在**第一次**发生并入时告诉他一次:

> 你已经有一个账号了(最早用 Google 创建的)。这次的邮箱登录已经加到同一个账号上。

按已验证邮箱自动并入是我们的选择,那就有责任让用户知道**有几条路能进他的账号**。

### ④ Space

**看到**:自己已加入的 Space,每个显示名和 URL。按创建时间排,不做「最近访问」。

**能做**:

- **新建**:只填一个显示名。**输入的同时就能看到会得到的 URL**,不是提交后才知道。
- **改自己的显示名**
- **查看有哪几种方式能进这个账号**,以及连上一个还没连的提供商
- **退出**

零个 / 一个 / 多个 Space,行为完全一样。**没有「第一个 Space」特例。**

**登录方式**:三条路各自只有两种状态 —— **已经能用**,或者**可以去连接**。

```
邮箱验证码      已经能用
Google          已经能用
GitHub          可以去连接
```

并且要说清:

> 任何一种都进这个账号。邮箱验证码始终可用,因为账号就是这个邮箱。

这句话同时说清了一件他该知道的事:**拿到这个邮箱验证码的人就能进来。** 那是自动并入的直接后果。

「省一次等验证码」不和这三条并列 —— **安全信息里不掺推销**。

### ⑤ 进入

进到 `/s/{slug}`。这一片里面是空的,但始终能看到当前是哪个 Space、能切换、能退出。

**URL 是当前 Space 的唯一事实。** 不存默认 Space,不因为只有一个就自动进去。

---

## 身份

**同一个已验证的邮箱就是同一个人**,不管从哪个入口进来。

Google、GitHub 都返回已验证的邮箱;邮箱验证码本身就是验证。**登录方式是这个人名下的凭据,不是身份。**

## 显示名

| 入口            | 初始值                                               |
| --------------- | ---------------------------------------------------- |
| Google / GitHub | 提供商给的名字 → 没有就用它的用户名 → 还没有就用邮箱 |
| 邮箱            | 完整的邮箱地址                                       |

可改,不唯一,是 User 的属性 —— 改一次,所有 Space 里一起变。

改名的时机是**用户第一次即将对别人可见的时候**,所以它和 Space 在一起,不在一个他永远不会去的设置页里。

> **给下一片留的口子**:从邀请链接进来的人不经过 ④,所以那一片要在它自己的地方放同一个改名入口。

## 失败与恢复

**发码**

| 发生什么     | 看到什么             | 能做什么               |
| ------------ | -------------------- | ---------------------- |
| 邮箱格式不对 | 检查一下这个邮箱     | 改了重发               |
| 对方拒收     | 这个邮箱收不到信     | 换一个                 |
| 响应丢了     | 这封信可能已经发出了 | 重试**不会发出第二封** |
| 重发太快     | 还要等 24 秒         | 等                     |

**验码**

| 发生什么         | 看到什么                      | 能做什么       |
| ---------------- | ----------------------------- | -------------- |
| 码不对           | 这个码不对,看一眼最新那封邮件 | 重输           |
| 码过期           | 这个码已经过期                | 重新要一个     |
| **码已经用过**   | 这个码已经用过了              | 重新要一个     |
| 试太多次         | 这次验证作废了                | 从邮箱重新开始 |
| 这次验证不存在了 | 从头开始                      | 回登录页       |

「已经用过」和「不对」不能合并:前者意味着**可能有人已经拿它登录了**。

**连一个提供商**

| 发生什么                   | 看到什么                                | 能做什么                    |
| -------------------------- | --------------------------------------- | --------------------------- |
| 那边的邮箱和这个账号不同   | 这个 Google 账号用的是别的邮箱,连不过来 | 换一个,或用那个邮箱单独登录 |
| 这个提供商已连在别的账号上 | 它已经连在另一个账号上                  | 先从那个账号断开            |
| 用户在提供商那边取消了     | 没有连上,什么都没变                     | 重来                        |

**建 Space**

| 发生什么          | 看到什么                            | 能做什么                      |
| ----------------- | ----------------------------------- | ----------------------------- |
| 名字空            | 填一个名字                          | —                             |
| 提交时 URL 刚被占 | 这个 URL 刚被占用,试 `xu-yue-tai-2` | 用建议 / 改名字               |
| 响应丢了          | 不确定建成了没有                    | 重试同一身份,**不会建出两个** |
| 并发同名          | 一个成功,另一个拿到冲突             | 后者改名字                    |

建议不预留,也不承诺提交时还在。

**进入与会话**

| 发生什么                 | 看到什么              | 能做什么                         |
| ------------------------ | --------------------- | -------------------------------- |
| slug 不存在 / 你不是成员 | **这个 Space 不可用** | 回到自己的 Space                 |
| 会话过期                 | 需要重新登录          | 登录后**回到原来要去的那个 URL** |

不存在和不是成员给同一个回答,否则 URL 就成了探测工具。

## 承诺

```
① 同一个已验证邮箱 = 同一个账号,不管从哪个入口进
② 你随时能看到有哪几条路能进你的账号
③ 一次「发码」最多一封信。响应丢了重试,还是一封
   确定发不出去的时候说发不出去,不让人对着空邮箱等
④ 一次「建 Space」最多一个。响应丢了重试,还是一个
⑤ URL 是当前 Space 的唯一事实
⑥ 不存在和不是成员,同一个回答
⑦ 显示名不冒充真名:初始值明显来自你的登录方式,而且随时能改
```

## 完成标准

```
三种方式各走一遍,从零数据进到一个 Space 里
同一个邮箱先 Google 后验证码 → 同一个账号,Space 都在,而且看到了并入提示
登录方式那一段,三条路的状态是对的
连上 GitHub 之后,下次登录不用等验证码
连一个邮箱不同的 Google → 明确拒绝,账号没变
杀掉响应各一次(发码、建 Space)→ 信只有一封,Space 只有一个
两个人同时用同一个名字建 Space → 一个成功,一个拿到带建议的冲突
改名之后,所有出现名字的地方一起变
访问不属于你的 /s/{slug} → 「这个 Space 不可用」
会话过期后重新登录 → 回到原来那个 URL
```
