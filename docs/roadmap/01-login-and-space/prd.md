# 登录与 Space

一条完整的纵向:**打开 → 登录 → 选或建一个 Space → 进去 → 刷新还在**。

进去之后是空的。这一片的终点是**能进、能切、能退**。

**本文件不定布局。** 只写用户能做什么、被告知什么、失败时怎么办。

---

## 旅程

### ① 登录

用户能选:Google、GitHub、或者输邮箱要一个验证码。

**在他做选择之前**,必须已经知道这一句:

> 任何方式,只要邮箱相同,进的都是同一个账号。

这句话决定他敢不敢换一种方式点。放在他选完之后才说等于没说。

### ② 验证码

系统告诉他:

> 我们给 mina@example.com 发了一个六位码。五分钟内有效,只有最新一封有效。

- 输满六位**自动提交**,不用再确认一次
- 能重新发送,并且看得到还要等多少秒
- 能换一个邮箱,**换回去时原来输的地址还在**

### ③ 如果这次登录并入了一个已有账号

只在**第一次**发生并入时告诉他一次:

> 你已经有一个账号了(最早用 Google 创建的)。这次的邮箱登录已经加到同一个账号上。

按已验证邮箱自动并入是我们的选择,那就有责任让用户知道**有几条路能进他的账号**。

### ④ Space

**看到**:自己已加入的 Space,每个显示名和 URL。按创建时间排,不做「最近访问」。

**能做**:

- **新建**:只填一个显示名。**输入的同时就能看到会得到的 URL**,不是提交后才知道。
- **改自己的显示名**
- **查看有哪几条路能进这个账号**,连上一个还没连的提供商,或者再绑一个邮箱
- **退出**

零个 / 一个 / 多个 Space,行为完全一样。**没有「第一个 Space」特例。**

**登录方式**:一条一条列出来,每条只有两种状态 —— **已经能用**,或者**可以去连接**。

```
mina@example.com    邮箱验证码    已经能用
zane@gmail.com      邮箱验证码    已经能用
Google              已经能用
GitHub              可以去连接
```

邮箱是**一条一条列的**,因为一个账号可以有好几个。并且要说清:

> 任何一条都进这个账号。收得到上面任何一个地址的验证码的人,就能进来。

这句话是他该知道的事,不是功能介绍:**每多绑一个邮箱,就多一把钥匙。**

「省一次等验证码」不和这些并列 —— **安全信息里不掺推销**。

### ⑤ 绑一个邮箱

已经登录的人可以再绑一个地址:填地址 → 收码 → 验。验过之后它也能进这个账号。

绑邮箱和用邮箱登录是**两件事**,分开做:登录是"我是谁",绑定是"再给我一把钥匙"。

### ⑥ 进入

进到 `/s/{slug}`。这一片里面是空的,但始终能看到当前是哪个 Space、能切换、能退出。

**URL 是当前 Space 的唯一事实。** 不存默认 Space,不因为只有一个就自动进去。

## 身份

**账号本身没有内容。** 它不是一个邮箱,也不是某个提供商那边的账号 —— 它就是一个 id,底下挂着几把
钥匙。邮箱、Google、GitHub 都是钥匙,地位相同,哪一把都开同一扇门。

一个账号可以挂**多个已验证邮箱**。一个邮箱只属于一个账号。

那为什么第一次拿 Google 进来,会进到一个已经存在的账号里?因为 Google 交回来的是一个**它已经验证过
的地址**,而验证这个地址正是邮箱验证码在做的事 —— 同一个标准,不更弱。所以:

```
提供商的 subject 认识        → 进它对应的那个账号
不认识,但交回的地址已经属于某个账号  → 进那个账号,并且把这把钥匙挂上去
都不是                      → 新账号
```

**已经登录之后再连一把钥匙,不看地址。** 你已经证明了你是这个账号的主人,你自愿再加一条路进来,
地址一不一样不改变这件事。

**绝不对未验证的地址做以上任何一件事。**

## 显示名

| 入口            | 初始值                                               |
| --------------- | ---------------------------------------------------- |
| Google / GitHub | 提供商给的名字 → 没有就用它的用户名 → 还没有就用邮箱 |
| 邮箱            | 完整的邮箱地址                                       |

可改,不唯一,是 User 的属性 —— 改一次,所有 Space 里一起变。

改名的时机是**用户第一次即将对别人可见的时候**,所以它和 Space 在一起,不在一个他永远不会去的设置页里。

> **给下一片留的口子**:从邀请链接进来的人不经过 ④,所以那一片要在它自己的地方放同一个改名入口。

## 失败与恢复

**发码**

| 发生什么     | 看到什么             | 能做什么               |
| ------------ | -------------------- | ---------------------- |
| 邮箱格式不对 | 检查一下这个邮箱     | 改了重发               |
| 对方拒收     | 这个邮箱收不到信     | 换一个                 |
| 响应丢了     | 这封信可能已经发出了 | 重试**不会发出第二封** |
| 重发太快     | 还要等 24 秒         | 等                     |

**验码**

| 发生什么         | 看到什么                      | 能做什么       |
| ---------------- | ----------------------------- | -------------- |
| 码不对           | 这个码不对,看一眼最新那封邮件 | 重输           |
| 码过期           | 这个码已经过期                | 重新要一个     |
| **码已经用过**   | 这个码已经用过了              | 重新要一个     |
| 试太多次         | 这次验证作废了                | 从邮箱重新开始 |
| 这次验证不存在了 | 从头开始                      | 回登录页       |

「已经用过」和「不对」不能合并:前者意味着**可能有人已经拿它登录了**。

**连一个提供商**

| 发生什么                 | 看到什么               | 能做什么         |
| ------------------------ | ---------------------- | ---------------- |
| 这个提供商账号已连在别处 | 它已经连在另一个账号上 | 先从那个账号断开 |
| 用户在提供商那边取消了   | 没有连上,什么都没变    | 重来             |
| 中途会话没了             | 需要重新登录           | 登录后重来       |

**不再要求邮箱相同。** 已经登录的人加一条自己的路,地址不需要和账号一致。

**绑一个邮箱**

| 发生什么             | 看到什么             | 能做什么              |
| -------------------- | -------------------- | --------------------- |
| 这个地址已经属于别人 | 它已经属于另一个账号 | 用它单独登录,或换一个 |
| 这个地址已经是自己的 | 它已经能进这个账号了 | —                     |
| 码不对 / 过期 / 用过 | 和登录时一模一样     | 和登录时一模一样      |

「已经属于别人」可以直说,不算泄露:能验过这个地址的人,本来就能用它登进那个账号。

**建 Space**

| 发生什么          | 看到什么                            | 能做什么                      |
| ----------------- | ----------------------------------- | ----------------------------- |
| 名字空            | 填一个名字                          | —                             |
| 提交时 URL 刚被占 | 这个 URL 刚被占用,试 `xu-yue-tai-2` | 用建议 / 改名字               |
| 响应丢了          | 不确定建成了没有                    | 重试同一身份,**不会建出两个** |
| 并发同名          | 一个成功,另一个拿到冲突             | 后者改名字                    |

建议不预留,也不承诺提交时还在。

**进入与会话**

| 发生什么                 | 看到什么              | 能做什么                         |
| ------------------------ | --------------------- | -------------------------------- |
| slug 不存在 / 你不是成员 | **这个 Space 不可用** | 回到自己的 Space                 |
| 会话过期                 | 需要重新登录          | 登录后**回到原来要去的那个 URL** |

不存在和不是成员给同一个回答,否则 URL 就成了探测工具。

## 承诺

```
① 一个已验证的地址只属于一个账号,不管它是自己填的还是提供商交回来的
② 你随时能看到有哪几条路能进你的账号 —— 每一个地址都单独列出来
③ 一次「发码」最多一封信。响应丢了重试,还是一封
   确定发不出去的时候说发不出去,不让人对着空邮箱等
④ 一次「建 Space」最多一个。响应丢了重试,还是一个
⑤ URL 是当前 Space 的唯一事实
⑥ 不存在和不是成员,同一个回答
⑦ 显示名不冒充真名:初始值明显来自你的登录方式,而且随时能改
```

## 完成标准

```
三种方式各走一遍,从零数据进到一个 Space 里
同一个邮箱先 Google 后验证码 → 同一个账号,Space 都在,而且看到了并入提示
登录方式那一段,每个地址和每个提供商的状态都是对的
连上 GitHub 之后,下次登录不用等验证码
用 Google 登进来,再绑一个完全不同的邮箱 → 两条路都能进同一个账号
绑一个已经属于别人的地址 → 明确拒绝,两边账号都没变
连一个已经连在别人账号上的 GitHub → 明确拒绝,账号没变
连接失败的每一种,都在页面上说了原因
杀掉响应各一次(发码、建 Space)→ 信只有一封,Space 只有一个
两个人同时用同一个名字建 Space → 一个成功,一个拿到带建议的冲突
改名之后,所有出现名字的地方一起变
访问不属于你的 /s/{slug} → 「这个 Space 不可用」
会话过期后重新登录 → 回到原来那个 URL
```

## 不在这一片

```
断开某个登录方式        规则先记下:永远不能断开最后一条路
挑一个地址当主地址      现在按验证时间取最早的那个
把两个账号合成一个      它需要的东西比这一片多
邀请 · 成员管理 · 两项窄权限
Space 改名 · 删除 · 结束
机器 · Agent · Work · 对话
```
