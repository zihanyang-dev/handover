# 对一个 agent 说话

一条完整的纵向:**挑一个 agent → 说一句话 → 看它做 → 想停就停 → 接着说 → 刷新还在**。

`02` 的终点是「找到了这台机器上装了什么」。这一片的终点是**它真的能用**。

**本文件不定布局。** 只写用户能做什么、被告知什么、失败时怎么办。

---

## 旅程

### ① 挑一个

Space 里能看到每台机器上有什么。挑一个在线的:

```
zane-mbp        Claude Code 2.1.231   ·   Codex 0.148.0
build-server-1  Codex 0.148.0
```

点开一个,就是一段对话。

### ② 说一句话

一个输入框。你打一句,发出去。

**它就在你的项目里干活,会真的改你的文件。**

具体是哪个目录:**你接入那台机器时所在的那个**。不用选,也不用填 —— `handover connect` 当场
就把它打印出来了。「读一下 src/payment 里的超时逻辑」能办,靠的就是这个。

**同一台机器一次只跑一段对话。** 不会两个 agent 在同一个目录里互相踩。第二段要等第一段说完。

### ③ 它一件一件地做,你看着

不是转圈等它想完。一件事一行:

```
说   我先看一下这个文件
读   payment/timeout.ts
跑   rg "timeout" src/
想   ……
说   超时是 30 秒,写死在 client.ts:42
```

**这是它自己的话翻过来的,不是原始日志。** 我们不认识的工具就显示它自己的名字,不会漏掉也不会假装认识。

**关掉浏览器它也在跑。** 回来接着看。

### ④ 停

它做到一半你改主意了,可以叫停。**它停下来,这段对话还能接着用** —— 叫停是为了让它换个方向,
不是把它扔掉。

记录里能看到两件事,而且是分开的两条:**你叫了停**,以及**它停了**。一轮被叫停之后没停下来,
正是需要看得见的那种情况。

**发一句话也是停。** 你不用先按停再打字 —— 直接说,它就停下来听。按钮上会写清楚这一点。

### ⑤ 挑模型和思考档位

每一句都能挑,不是开对话时定死 —— 便宜的问题和难的问题会出现在同一段对话里。

**能挑什么由那个 agent 自己报。** 它报得出清单就有得挑,报不出就没有这个控件 ——
挑一个 agent 本来就是在挑它能做什么。什么都不挑就是用它自己的默认。

### ⑥ 接着说

它记得上一句。你不用重复上下文。

**记不住的时候会说出来** —— 见「接不上」。

### ⑦ 回来

刷新、换个设备、过一天回来,**这段对话都在**。

但**看着它干活**和**回来翻记录**给的东西不一样,这个差别要说清楚:

|                | 它正在干的时候 | 过一天回来   |
| -------------- | -------------- | ------------ |
| 它说了什么     | 有             | 有           |
| 它做了什么     | 有             | 有(一件一行) |
| 命令的完整输出 | 有             | 只有开头一段 |
| 它在想什么     | 有             | **没有**     |

**思考不留档。** 它在场的时候有用 —— 你知道它没卡住、在往哪个方向走。事后没人回去翻。
Claude Code 自己写的记录里也只留了签名、不留可读的思考,这不是我们省事。

## 一段对话

```
在哪台机器上的哪个 agent      挑了就不能改。想换就是开一段新的
一条一条                      你说的、它说的、它做的,按顺序
```

**换 agent 就是开一段新对话。** 不做「把上下文搬过去」—— 那是在假装两个 agent 是同一个。

---

## 失败与恢复

**发一句话**

| 发生什么                    | 看到什么                       | 能做什么           |
| --------------------------- | ------------------------------ | ------------------ |
| 机器不在线                  | 这台机器现在不在线             | 等它回来 / 换一台  |
| 那个 agent 不在那台机器上了 | 这台机器上现在没有 Claude Code | 换一个 / 装回来    |
| 机器被移除了                | 这台机器不在这个 Space 里了    | 换一台             |
| 响应丢了                    | 不确定发出去没有               | 重试**不会说两遍** |

**它做事的过程中**

| 发生什么       | 看到什么                                        | 能做什么                         |
| -------------- | ----------------------------------------------- | -------------------------------- |
| agent 起不来   | 起不来,以及起不来的原因                         | 再说一遍                         |
| agent 中途死了 | 这一轮没做完,以及它死在哪                       | 再说一遍                         |
| 机器掉线       | **不知道**它那边做到哪了                        | 不自动重发。你决定要不要再说一遍 |
| 接不上上一句   | **「它不记得前面说了什么,这一句是重新开始的」** | 不用做什么,但你知道它忘了        |
| 你把浏览器关了 | 它继续跑                                        | 回来接着看                       |

「不知道」和「死了」不能合并:后者再说一遍是安全的,前者可能让同一句话被处理两次。

**接不上是什么意思**

agent 自己记着上下文。那份记忆在它那台机器上,会过期、会因为机器重装而没。

接不上的时候我们**不假装接上了**。页面明说这一句是从头开始的。

## 承诺

```
① 你说的每一句话,只会被送到一个确定的 agent 上,不会串
  同一台机器一次只跑一段对话,两个 agent 不会在一个目录里互相踩
② 它干的每件事你都看得见,不用它另外汇报
③ 关掉浏览器它照跑,回来什么都没少
④ 它不记得前面的时候会说出来,不冒充一段连续的记忆
⑤ 「不知道」永远不被猜成成功或失败,也不自动重发
⑥ 一段对话固定一个 agent,换 agent 就是换一段
⑦ 实时能看到的和事后能看到的,差别提前说清,不让人以为是丢了
⑧ 叫停之后它停下来,而且这段对话还能接着用 —— 停不是失败
⑨ 「你叫了停」和「它停了」是两条记录。叫了没停下来,你看得见
⑩ 它在干活的时候你随时能说话,而说话就是打断 —— 输入框不会因为它在忙而变灰
```

**「等它说完再说」不是一条产品规则,是一次没做完的实现。** 排队听起来更温柔,坏起来很难看:
你打「别动 legacy/」,它没听见,接着改了五分钟 legacy/,做完那一步才读到你那句 —— 你眼睁睁
看着它做你刚说了不要做的事。打断的代价只是那一步白跑了,而这个产品里停下来是安全的(⑧)。

**承诺的是「一件一件地出」,不是「一个字一个字地出」。** 逐字取决于那个 agent 给不给 ——
Claude Code 给,Codex 只到条目级。给的时候页面自然更顺,但它不是承诺,也不该让人以为哪里坏了。

## 完成标准

```
挑一个在线的 agent,说一句话,看着它一件一件做出来
它说的、读的、跑的都在页面上,不是只有结论
用一个我们没见过的工具(比如某个 MCP 工具)→ 显示它自己的名字,不漏也不乱
说第二句,它记得第一句
关掉浏览器,过一会儿回来 → 说的和做的都在
刷新页面 → 一样
换一台设备打开 → 一样
拔掉网线 → 那一轮显示「不知道」,不自动重发
杀掉 agent 进程 → 说清楚它死了,再说一遍能继续
卸载 agent → 明确说这台机器上没有它了
机器离线 → 明确说,不是转圈
它做到一半点停 → 它停下来,那一轮显示为停掉的,不是失败;接着说还能继续
常驻进程被 kill -9 再拉起来 → 当时那一轮显示「不知道」,而没人开始的问题仍然在等
claude 那边挑一个别的模型和档位 → 那一句真的用了它
codex 报得出模型清单,pi 那样报不出的就没有这个控件
claude-code 和 codex 各走一遍完整旅程
```
