# 一次好几件 · 设计

`prd.md` 说要什么。这里说怎么建,以及为什么不是别的建法。

---

## 工作区就是一个文件夹

没有别的东西。不是容器,不是 worktree,不是 checkout —— 一个空目录,agent 自己往里放。

### 服务端不决定工作区在哪

不是「不存路径」—— 下面会看到有两列路径进了 schema。规矩比那句准确:**默认落在哪儿,是机器自己算的,服务端没有意见。**

服务端只说「这是对话 X」:

```
~/.handover/work/<conversation id>/
```

沙箱来的时候用同样的规则,只是根目录不同 —— 它不需要我们改任何一列,因为从来没有一列写着「工作区在哪」。这就是给沙箱留的全部位置。

进 schema 的那两列都不是我们在决定位置:一列是**人的选择**(他说了,我们记住),一列是**机器对自己的陈述**(它报的,和 `version` 一样)。两者都不妨碍机器换一套算法。

### 工作区 ≠ 当前目录

默认两者相同。指到自己项目时不同:

```
默认                工作区 = ~/.handover/work/<id>/     agent 的 cwd 也是它
指到自己的项目       工作区还是 ~/.handover/work/<id>/   里面只放 subtask/
                    cwd = /Users/mina/code/thing
```

分开是为了一件事:**子任务永远开在工作区里,不会跑进你自己的仓库。** 不然 `subtask/` 会变成你工作树里一个莫名其妙的未跟踪目录,`git status`、构建、测试都会撞见它。

`conversations.works_in` 没有了。它记的是「人指到哪儿」,而那个问题不再问 —— 见 `prd.md` ②。

`machines.connected_in` 也没有了。它是给那个已经砍掉的选择当候选值的,砍那个选择时留了下来,理由是「重连时列出已连过的机器,目录是人分辨它们的方式」—— **那个屏幕从来没做出来**。机器报它、契约带它、浏览器接住它,没有一个像素显示过它。

一条读者能拿去对代码、然后什么都找不到的理由,比没有这一列更糟:它是一句写在会被人相信的地方的、产品并没有兑现的承诺。重连的屏幕哪天真要,那天再要,而且是当真要。

### 不在就建,还是不在就报错

**我们自己命名的文件夹,不在就建;人打的路径,不在就报错。** 打错一个字母而我们默默建出来,agent 会在一个空目录里干活、找不到任何东西 —— 读起来像「agent 把我文件弄丢了」,而不是真正发生的那件事。所以这一轮直接结束,写一行说「这台机器上没有这个目录」。

有一个洞,写下来而不假装没有:`mkdir -p` 会把上级一起建出来。人删掉父任务的工作区、而某个子任务先拿到一轮 —— 子任务把父任务那层顺手建回来了,父任务下一轮再看,文件夹「在」,于是它那段对话里**不会**有那行 `started-over`。没有东西坏掉(agent 打开就看见空的),丢的只是一句说明。绕开它要么让子任务在父目录缺失时跑不了(更糟),要么让子任务代替父任务往别人的对话里写字(更绕)。所以留着,并写在这里。

## 子任务住在里面

```
~/.handover/work/<父对话>/
    <agent 弄的东西>
    subtask/
        <子对话>/
        <另一个子对话>/
```

子任务的工作区是**父对话工作区下的一个子目录**,不是它自己那一份。所以:

- 子任务读父任务的东西,是读上一层,不用任何机制
- 兄弟之间各写各的,不会撞
- 一个人打开父任务的文件夹,底下所有东西都在那儿

机器要算出这个路径,就得知道「这段对话是谁的子任务」。所以**派给机器的那份活里要带上父对话的 id** —— `Asking` 加一个可空字段。

### 「只写自己那个」:一个真关得住,一个关不住

把子任务的 cwd 设成它自己那个文件夹。往上读是允许的 —— 那正是我们要的共享上下文。往外**写**呢:**两个都写得出去**,`cwd` 是落点,不是边界。

```
Codex          apps/cli/src/agents/codex.ts        sandbox: 'danger-full-access'
Claude Code    apps/cli/src/agents/claude-code.ts  permissionMode: 'bypassPermissions'
```

一样,是刻意的。机器旁边没人回答授权提示(03 定下的),而一道拦得住 agent 的墙,在没人能放行的时候不是安全,是一个卡死的回合。Codex 原本那个 `workspace-write` 还不只是挡写 —— 它默认把网络也一起关了,于是「装个依赖」这种事在 Codex 上失败、在 Claude Code 上成功,一个没人选过、界面上也看不见的差异。

**「只写自己那个角落」是默认落点,对谁都不是保证。** 写清楚,因为把它说成一道墙,会让人以为有一道并不存在的边界。

真要隔离,隔离的是一整个环境 —— gVisor 那类,agent 在里面握有全部权限,墙立在环境外面。那和在你自己的机器上、绕着你自己的文件画一条线,是两件事。这一片不做,记在这儿。

**不做能力上报,不做版本闸,不拒绝任何 agent。** Multica 需要那道闸,是因为老 daemon 会改掉**用户明确要求隔离的那份工作副本** —— 违背的是用户的预期。这里不是:子任务写到父任务的目录,是你自己的 agent 在你自己的机器上把你自己的文件弄乱了。那是一团糟,不是一道信任边界。

## 上限挂在 agent 上

### 为什么不是机器

一台机器上可能装了 Claude Code 和 Codex。「这台机器同时能跑几件」把两个不同的东西混成一个数;「这个 agent 同时能接几件」才是人想调的那个。

Multica 的 schema 是同一个结论:

```sql
-- 001_init
max_concurrent_tasks INT NOT NULL DEFAULT 1
-- 023_agent_concurrency_default
ALTER TABLE agent ALTER COLUMN max_concurrent_tasks SET DEFAULT 6;
```

它从 1 起步,后来把默认改成 6。**我们默认 3**:1 会让这一片什么都没交付(大多数人一台机器一个 agent),2 会让第三件等。3 是判断,不是量出来的;它是个设置,看着调。

Multica 还有一个机器级的上限(默认 20)。我们不做第二个 —— 同一个问题的第二个答案。

### 观察和决定不能放在同一行

`agents` 这张表是**一次 PATH 扫描的结果**。扫描会出错:服务里 PATH 不对、`brew upgrade` 跑到一半、磁盘慢超时。任何一次抖动,那个 kind 就不在报告里,行被删掉。

`agent_names` 的迁移已经写下这条:

> A discovered agent and the name its owner chose have different lifetimes.

上限和名字是同一种东西 —— **主人定的**。所以它放在那张表里,而那张表现在装的不只是名字了:

```
agent_names  →  agent_settings
                name        主人起的名字(可空 —— 只设了上限的人没有名字可编)
                at_once     同时最多几个,默认 3,上限 16
                decided_at  原来叫 named_at。这张表装的不只是名字了
```

它今天刚建、还没发布,改名是最便宜的时候。

上限 16 写在两个地方 —— 门上的校验和列上的约束 —— 所以它们要被拴在一起(`AT_ONCE_AT_MOST`,`machine.spec.ts` 里有一条测试同时按住两头)。分开漂移的后果很具体:门收下 20,数据库拒绝,人看到的是自己的电脑坏了。

这个数没有测出来的依据。一台机器两个 agent 各开满是 32 个 agent 进程,每个还会自己 spawn 构建和测试 —— 它只是一个「明显还不至于把机器跑死」的天花板,让输入框里的手滑不至于变成事故。

### 为什么不能再用唯一索引

今天那条索引够用,是因为上限是 1。上限是 N 时,唯一索引表达不了「至多 N 行」。

但那条索引的迁移解释过为什么**必须由数据库来管**:

> 两个实例各自对着自己的快照求值,谁也看不见对方未提交的插入,于是各认领了一段对话,两边都成功

所以认领时的做法是:**先锁住这台机器,再数这个 agent 有几个没结束的轮次。** 第二个认领者卡在锁上,等前一个提交完再数,数出来是满的。

锁的是**机器**,不是 `agent_settings` 那一行 —— 那行可能根本不存在(没起过名、没调过上限的 agent 就没有行),`for update` 锁不住不存在的东西。用 `pg_advisory_xact_lock(机器 id)`:不需要任何行,和 `db/conversation.ts` 开对话时用的是同一个手法。粗一点没关系 —— 会排在这把锁后面的,只有另一个实例在回答**同一台机器**的轮询,而一台机器一次只轮询一次。

不加槽位列,不加索引,不挑「最小的空位」。

## 忙不忙是算出来的,但这一片不往外发

```
在不在    presence      已经有了,靠 last_seen_at 和沉默阈值
忙不忙    数没结束的轮次  认领的时候算,和上限比
```

**这个数只在认领那一刻用,不出现在任何响应里。** 本来是发出去的,但没有一个屏幕读它 —— 一个没人消费的字段不该上 wire,而且它是每个 agent 一次关联子查询,挂在每次打开 Space 都会发的请求上。等「我的机器」那块屏幕来了再加,一行的事。

不管发不发,它都是**算出来的,不是存的**:计数会漂 —— 一个轮次因为进程被杀而没有减回去,这个 agent 就永远显示忙。

[Coder 把「在不在」和「到哪一步」分成两个枚举](https://github.com/coder/coder)(`WorkspaceAgentStatus` / `WorkspaceAgentLifecycle`),理由一样:**合并之后没有任何一个值说得清一台连着但还没准备好的机器。**

## 不删

对话在,文件夹就在。人删掉对话时一起走。

没有过期时间,没有孤儿清扫,没有空闲时才敢跑的重活。Multica 有五种过期时间、一套锁文件判活、`git gc` 只在空闲时开始 —— 那是「干完留着让你事后看 diff」换来的代价。我们也留着,但因为我们不自动删,所以不需要判断什么时候能删。

### 删掉了也没关系

人随时可以自己删,那是他的硬盘。删完之后 agent 的记忆还在(会话 id 存在对话上),但它记得的文件没了。

写一行,从空的开始。这一行**不是** `forgot` —— 那句说的是「agent 记不起上一轮」,是它的记忆;文件夹没了说的是活儿本身,agent 的记忆好好的。同一类事,不是同一件事,所以是自己的一个值:`started-over`。

机器怎么知道该写这一行:`mkdir` 会告诉它有没有真的建出目录。第一轮建出来是正常的,**不是第一轮还要建**(`agentSession` 不为空),那就是两轮之间有人删了。

这条一旦成立,反过来让「不删」变干净:**任何一个文件夹都可以被随手删掉而不弄坏什么**,所以我们不需要任何垃圾回收。

## 交办不再点名机器

`handOffTo` 今天收一个机器名,并且在 Space 范围内按名字找。这一片之后它只收 agent 的种类,活留在父任务那台机器上。

这不是为了省事,是 `prd.md` ⑥:**没有人在场的时候,不该有人的电脑被调度。** 一个人把活交给你,`06` 之后那一行写着他的名字;一个 agent 半夜把活丢到你笔记本上,没有人在场。

顺带删掉的:「借出别人的机器」这整套,以及跨机器时「子任务怎么看见父任务的文件」这个没有好答案的问题。

**人还是能点名你的机器。** 同 Space 的成员开对话时照样挑得到它 —— 那是 `02` 和 `05` ③ 说好的「你能用,但拿不走」,是共享本身,不是漏。坏掉的一直只是没有人在场的那一半。

这条改完之后,**一个人挑机器的地方只剩一处** —— `beginConversation`。`reachableFrom` 今天有四个调用点:

```
开对话                     人挑的,留着              db/conversation.ts
agent 点名的那台            这一片删掉               db/conversation.ts
Space 的机器列表            看,不是用                db/machine.ts
人被移出,机器跟着走          跟「谁能用」无关          db/membership.ts
```

目标 agent 不在这台机器上时,拒绝的理由已经有了 —— `no-agent`。

## 「在哪儿干活」说成一个值,不是两个可空字段

先写成了 `worksIn` 和 `subtaskOf` 两个可空字段并排,机器手里握着「哪个赢」这条规则。那是一个事实说坏了:**两个字段之间有优先级,就等于可以同时说两句话**,而规则住在一个两件事都不由它决定的地方。同时说了,结果是静默的,不是被拒绝的。

改成一个值。曾经是三个,`somewhere-named` 随着那个选择一起没了:

```
its-own    没人说过。自己的文件夹,拿对话 id 命名
under      agent 把它当子任务开出来的,住在那件活的文件夹底下
```

哪一个,由服务端说。**变成路径**仍然只发生在机器上:沙箱用同一个值,换一个根目录。

`somewhere-named` 走的时候带走了不少东西 —— 机器那边「这路径是绝对的吗」「那个目录真的在吗」两条检查,以及它们对应的两种失败。**它们存在的唯一理由是那条路径是人打出来的**,人不再打了,剩下的路径全是这个进程自己命名、自己创建的,不可能出错。

## 接口

```
PATCH /me/machines/{id}/agents/{kind}    今天只收 name,变成 name 和 atOnce 都可选的 patch
GET   /spaces/{slug}/machines             每个 agent 多当前 atOnce
POST  /machines/current/poll              asking 多一个 where:一个值,不是两个可空路径
                                          stopping 从一个变成一组,而且永远有(空数组)
```

拒绝多一个:`already-a-subtask`,恢复动作 `carry-on-here`(「没有别人可以给了,你自己在这儿做」)。
少一个:`no-such-machine` —— 交办不再点名机器,就没有「没这台机器」这回事了。

### 这是一次协议断裂,而且是最后一次可以随便断的时候

老 CLI 遇上新服务端会**坏**,不是降级:服务端会派第二、第三个问题,老循环一次只答一个、把其余的忽略掉,而那些轮次已经被认领了 —— 那几段对话会一直显示「在跑」,直到那台机器的进程重启。`stopping` 从一个变成一组,老代码也读不懂,所以「停」对它彻底失效。

**没有做版本闸,是因为没有消费者:`git tag` 是 0,版本号还是 `0.0.0`,世界上不存在一台跑着老 CLI 的机器。** 为零台机器造一条兼容路径,是往协议里永久加一个字段去伺候一个从未存在过的构建。

这条的有效期到第一个 tag 为止。**第一次发布必须同时带上服务端和 CLI 两半**;在那之后再改 `poll` 的形状,就得先有「机器说自己能做什么」这件事 —— `02` 的「不在这一片」里已经给它留了位置(「agent 的版本约束和能力声明」)。

## 那个开关的形状

不在这一片,但已经想清楚了。记在这儿,省得下一片从头推一遍。

```
一列               machines.shared,默认 true
拆成两个           reachableFrom 今天既管「看得见」又管「用得了」。列表用弱的那个,
                  开对话用强的那个 —— 而强的要带上问的人是谁,因为主人自己永远用得了
关掉之后           机器还在列表里,灰着,写「只有 <主人> 能用」。和「离线」是同一种呈现;
                  凭空消失会被读成机器挂了,同事会来问你
门                 PATCH /me/machines/{id}。不是 /spaces/{slug}/... —— 「我的机器」
                  不属于任何 Space。以后真要按 Space 分开,boolean 变成列表,老数据全是开
不停正在跑的        它只说「从现在起不进新的」。停是主人另一个动作,有它自己的历史
自己的拒绝理由      复用 UNAVAILABLE(「没有这台机器」)是对着一台他看得见的机器说假话
```
