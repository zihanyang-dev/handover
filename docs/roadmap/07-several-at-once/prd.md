# 一次好几件

`04` 的终点是**你交给它,然后走开**。这一片的终点是**你交给它三件,然后走开**。

## 为什么是现在

不是因为清单排到了。是因为 `04` 那句话现在只对第一件事成立。

### 承诺只兑现了第一件

数据库里有这一行:

```sql
create unique index turns_one_open_per_machine on turns (machine_id) where ended_at is null;
```

一台机器,同一时刻,只有一个进行中的轮次。所以:

```
09:00  交给它「把超时改成可配置」    开始跑
09:01  交给它「改一遍登录页文案」     排队
09:02  交给它「升级那三个依赖」      排队
09:03  合上电脑
```

走开三小时,回来做完了一件半。**「交给它然后走开」这个动作,从第二件起就不值钱了。**

### 挡住它的那句注释,说的是另一件事

那条索引的迁移里写着它为什么存在:

> two agents run in the same directory overwriting each other's files

它防的不是并行,是**共用一个目录**。而目录只有一个,是因为今天一台机器就一个:

```ts
// apps/cli/src/main.ts
where: process.cwd() // 你跑 handover connect 时所在的那个目录
```

`03` 那一片是这么设计的,而且对 —— 你陪着它做的时候,它就该在你的树里,看得见你没提交的改动。但一件交出去、没人看着的活,不该和它抢同一份文件。

**分开目录,那条约束的理由就没了。**

### 还有一句是假的

`05` ③ 写着:

> 那是他的电脑,你能用,但拿不走。

今天不只别人能用 —— **别人的 agent 也能用**,而且没有任何同意。`handOffTo` 只检查「这台机器从这个 Space 到得了」和「上面有这个 agent」。

两种「别人」不是一回事,这一片只解决一种:

```
别人的 agent    半夜挑中你的机器,没有人在场,事后没有名字   这一片挡掉
别人这个人       他点了你的机器,有时间,06 之后写着他的名字   这一片让你看见,不拦
```

`02` 留过一个「这台不欢迎」的开关。它挡的是后一种 —— 而后一种正是上面那句说好的「你能用」,是共享本身。所以它不在这里,它和「我的机器」那块屏幕一起做(见「不在这一片」)。

---

## 旅程

### ① 一个对话,一个地方

每段对话有自己的文件夹。agent 要什么自己往里放 —— clone 一个仓库、下载一份数据、写几个文件,它有工具。

**一个文件夹里可以有好几个仓库**,也可以一个都没有。我们不管里面是什么,那是 agent 和你的事。

慢没关系。一件交出去的活可能跑一天,多花两分钟 clone 不是问题。

### ② 不问你在哪个目录干活

这里曾经写着另一个答案:开对话那一刻多一个二选一,「它自己的文件夹」还是「你连接这台机器时所在的那个目录」。**砍掉了,而且是砍掉而不是延后。**

砍的理由有三条,第三条最重。

一,第二个选项的含义是「你当初敲 `handover connect` 时 shell 恰好在哪」。那是个历史偶然 —— 可能是 `~`,可能是随手 `cd` 进去的某处 —— 而人在几个月后开对话时不会记得那是哪。

二,**这个产品的用户不只是写代码的人**。本片自己就写着「设计师的素材文件夹用不上它」。对不持有一个 checkout 的人,这个问题没有答案,而它出现在每一次开对话的路径上。

三,没有一个同类产品在开始任务时问这个。Claude Code 和 Codex 在你启动它的目录里干活,目录由 `cd` 决定;Devin 是 workspace 配一次,之后每个 session 从同一个快照启动 ——「Configure it once, and every session boots into that known-good state」。**要么由启动位置隐含,要么配置一次,没有人每次都问。**

那「让它读到我未提交的改动」这件事呢?它是真的,但它是少数人的、偶尔的需要,而当时的做法是让所有人每次都回答一遍。等有人真的要,再单独想一个不打扰其他人的做法 —— 那时的答案多半不是一个二选一。

### ③ 交三件,三件一起动

每件活在自己的文件夹里,各自在各自那儿干。

**这是分开,不是墙。** Codex 被它自己的沙箱关在里面,写不出去;Claude Code 我们是 `bypassPermissions` 跑的,它写得出去。两件活互相踩不是我们拦下来的,是它们各自在各自的地方,没有理由去碰对方。

### ④ 子任务住在父任务的地方,但各有各的角落

```
这段对话的工作区/
    ...agent 弄的东西...
    subtask/
        子任务A/
        子任务B/
```

子任务**看得见**父任务的东西 —— 就在上面一层,不用谁传给谁。子任务干活的地方是它自己那个角落。

**两个都关不住,而且是刻意的。** Codex 我们是 `sandbox: 'danger-full-access'` 跑的,Claude Code 是 `bypassPermissions` 跑的 —— 没人在机器旁边回答授权提示,而一道拦得住 agent 的墙,在没人能放行的时候不是安全,是一个卡死的回合。这不是一道信任边界:是你自己的 agent 在你自己的机器上把你自己的文件弄乱。

真要隔离,隔离的是**一整个环境**(gVisor 那类) —— agent 在里面本来就该握有全部权限,墙立在环境外面。在你自己的机器上、绕着你自己的文件画一条线,不是那件事。

### ⑤ 只有父任务能开子任务

没有孙任务。一个子任务想再拆,只能自己做完,或者结束了回来说。

扇出的计划留在那个要负责的人手上,不在链条第三层由某个 agent 自己决定。

### ⑥ 子任务不去别人的电脑

agent 交办的活,留在原来那台机器上,换 agent 可以,换机器不行。

**你的电脑不会被某个 agent 调度。** 人可以把活交给你 —— 那有名字、有时间、`06` 之后查得到是谁;agent 不行,因为那时候没有人在场。

### ⑦ 同时最多几个,是你定的

每个 agent 上一个数,默认 3。你的笔记本,你说了算。

### ⑧ 文件夹是你的

我们不删。对话还在,文件夹就在,你随时能打开看它到底改了什么。

**你也随时能删掉它。** 删了不会弄坏任何东西 —— 下一轮从空的开始,transcript 里写一行说明,和「agent 接不上上一轮」是同一类事。

## 承诺

```
① 一段对话有一个自己的地方 —— 分开,不是墙(见 ③ 那条注)
② 交出去的活同时跑,不排队 —— 上限是你定的那个数
③ 子任务看得见父任务的东西,自己在自己那个角落里干活
   (Codex 真的被它自己的沙箱关住;Claude Code 我们是 bypassPermissions 跑的,关不住)
④ 只有父任务能开子任务,没有第三层
⑤ agent 交办的活不去别人的电脑
⑥ 我们不删你的文件夹;你删了也不会弄坏什么
⑦ 开对话时不问你在哪个目录干活 —— 每段对话都有自己的文件夹,见 ②
```

上限在 Space Settings 的 Machines 里改(`PATCH /me/machines/{id}/agents/{kind}`),和断开、转交、给 agent 改名放在同一块。只有机器主人能改自己的 agent;Space owner 只在处理成员归属时转交机器。

## 完成标准

```
交两件活,一个 agent,上限 3            → 第二件在第一件还开着的时候就开始了
                                       各在各的文件夹里
上限改成 1                            → 第二件等第一件结束
一台机器上两个 agent,一个满了           → 另一个照接
一件活交给子任务                       → subtask/ 下多一个文件夹
子任务干完、人再往里说一句                → 还在原来那个文件夹,没换地方
子任务再想交办                         → 被拒(而且绕过代码直接写 SQL 也插不进去)
交办时指定别人的机器                    → 没有这个选项了
开对话时选「我的项目」                   → 那个路径真的上了 wire
什么都不选                             → 一个空的、它自己的文件夹
机器太老,没说自己在哪儿被连接的           → 不显示这个选择,而不是显示一个假路径
人打的目录不存在 / 不是全路径             → 这一轮结束并说清楚,不替他建
手动删掉一个工作区,再说一句              → 从空的开始,transcript 里写着这件事
两个服务端实例同时把活派给同一台机器       → 超出上限的那个必然失败
```

**两条没有测试,而且不该有:** 「子任务读得到父任务的文件」是它在下一层这个事实本身;「子任务写不进父任务的目录」是 Codex 自己的沙箱在挡,不是我们的代码 —— 而对 Claude Code 它根本不成立(见 ③)。写一条测试去断言别人的沙箱,是在测别人的产品。

## 做的时候改了几条既有规则

**`04` ⑫「一台机器一次一件」不再成立。** 它当初是对的,因为一台机器一个目录。目录分开之后,限制搬到 agent 上,而且变成一个可以调的数。

**`04` 的交办不再点名机器。** `handOffTo` 今天收一个机器名。这一片之后它只收 agent 的种类 —— 活留在原地。这是 ⑥ 那条承诺的实现方式,也顺带删掉了「借出别人的机器」这整个问题。

**`03` ② 的两句话都不再成立,而且是这一片最该被人看见的改动。**

> 具体是哪个目录:**你接入那台机器时所在的那个**。不用选,也不用填。

现在要选了 —— 默认是它自己的空文件夹,「你的项目」是开对话时点一下。不这样不行:`03` 那句话成立的前提是一台机器只有一个目录,而那正是这一片要拆掉的东西。

> **同一台机器一次只跑一段对话。** 不会两个 agent 在同一个目录里互相踩。

一次跑几段由 `at_once` 决定,默认 3。「不会互相踩」的理由也换了 —— 不再是排队,是各在各的文件夹。`03` 承诺 ① 那半句跟着失效。
